# v0.7 Issue #39 actual-Herdr soak runbook

Status: committed preparation only. This document defines a future authorized
run; this preparation branch does not perform the soak, session control, human
UAT, package acceptance, release tagging, or issue closure.

## Evidence boundary

The soak producer is a read-only observer attached to an already running target.
It may launch the repository's `HerdrOps.Core trace-herdr-runtime` observer
binary for bounded windows, but it never invokes `herdr session`, never stops or
restarts Herdr, and never stops or restarts `HerdrOps.Core` or `HerdrOps.App`.
Only the operator may perform the scheduled target-session action. The output
always keeps `HumanUatDecision: NOT OBSERVED / PENDING` and
`ReleaseEvidence: NOT OBSERVED / NOT CLAIMED`.

## Preconditions

1. Use a fresh, isolated Acceptance control pane. Do not stop or relaunch the
   default Herdr server/session. Record `HERDR_ENV=1`, `HERDR_SOCKET_PATH`, and
   `HERDR_PANE_ID` from that control pane.
2. Use a clean checkout of the exact candidate commit. Record both:
   `git rev-parse HEAD` and `git rev-parse HEAD^{tree}`. A changed source tree,
   changed candidate binaries, or a rebuilt package invalidates prior evidence.
3. Run exactly an 8.0-hour soak. The producer has a hard duration ceiling and
   rejects longer or shorter live runs. Build the Release candidate and retain
   the exact observer executable (`HerdrOps.Core.exe`) with its candidate path,
   length, and SHA-256 bound in the soak artifact. The measurement artifact
   must be `Mode: Live`, pass `Test-V07MeasurementArtifactAdmission`, and
   contain distinct Core/App role PIDs and exact binary hashes.
4. Keep the target Agent Lab Herdr session and the measured Core/App processes
   alive for the entire run. The target socket and the control socket must be
   different. Each bounded observer report must retain the admitted Herdr
   server PID, process-start time, executable path, and SHA-256. The operator,
   not this harness, performs the target-session restart/fault action.

## Exact future commands

Run these only in the isolated Acceptance pane after the preconditions are
visibly satisfied. They are not part of the preparation validation command set.

```powershell
$repo = 'Z:\HerdrOps'
$candidate = Join-Path $repo 'artifacts\bin'
$measurement = 'Z:\evidence\v0.7\issue-39\measurement-run.json'
$soak = 'Z:\evidence\v0.7\issue-39\soak-<run-id>'

pwsh -NoProfile -File "$repo\tools\Invoke-V07ActualHerdrSoak.ps1" `
  -TargetHerdrSocketPath $env:HERDR_TARGET_SOCKET_PATH `
  -RepositoryRoot $repo `
  -CandidateDirectory $candidate `
  -MeasurementArtifactPath $measurement `
  -OutDirectory $soak `
  -HeartbeatSeconds 60 `
  -ObservationWindowSeconds 60
```

At each printed `SCHEDULED OBSERVATION DUE` line, perform only the documented
action against the target Agent Lab session. Never control the Acceptance pane.
The producer writes an immutable `soak-context.json`; the marker command must
use the exact schedule kind and offset from that context and fails before the
due time. After the action and its independent evidence file exist, record the
marker:

```powershell
pwsh -NoProfile -File "$repo\tools\Write-V07SoakOperatorObservation.ps1" `
  -SoakOutputDirectory $soak `
  -ScheduleId FAULT-01 `
  -ScheduledOffsetSeconds 7200 `
  -Kind TargetHerdrRestartObservation `
  -EvidencePath "$soak\operator-evidence\FAULT-01.json" `
  -Note 'Operator observed target reconnect; evidence file is retained below the soak root.'
```

Repeat the marker command for `FAULT-02` and `FAULT-03`, using the exact IDs,
offsets, kinds, and evidence paths printed by the harness. Markers are accepted
only when `ObservedUtc >= DueUtc`; missing markers remain `Missing` and fail
closed. The marker and finalizer rehash referenced evidence bytes, so editing
the evidence after the marker also fails closed.

## Handoff and gates

1. Preserve `soak-artifact.json`, `soak-gate-report.txt`, all JSONL logs, the
   runtime observer report, operator markers, and the evidence files referenced
   by those markers as one immutable evidence directory.
2. Recompute and record the SHA-256 of every retained file, including
   `soak-context.json`, the final observer report, and every referenced operator
   evidence file. Do not hand-edit the artifact after the producer returns.
3. Submit the exact measurement artifact and soak artifact to the existing
   finalizer and `Test-V07PerformanceBudgets.ps1`. A mismatch in run id,
   canonical measurement hash, source commit/tree, installed Herdr hash,
   session sockets, heartbeat chain, log bytes, or fault evidence blocks the
   Runtime gate.
4. Keep any later human UAT checklist, signed decision workflow, and release
   review separate from this Issue #39 producer. This automation emits no human
   approval and cannot satisfy those gates by changing a field.
5. The later v0.7 release gates remain blocked until the Plan-defined
   clean-machine, soak, budget/waiver, design review, and UAT evidence is
   independently accepted. Do not close, tag, publish, or create a release from
   this runbook.

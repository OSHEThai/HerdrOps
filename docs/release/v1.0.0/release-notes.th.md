# บันทึกประจำรุ่น HerdrOps v1.0.0

## เงื่อนไขการเผยแพร่

เอกสารนี้อธิบายรุ่นเสถียรภายในเครื่องที่ตั้งใจจะเผยแพร่ โดยนำไปใช้ได้เฉพาะกับชุดไฟล์ที่ระบุในบันทึกอนุญาตของ v1.0.0 หลังจาก Issue #41 ถึง #44 ผ่านครบ เจ้าของผลิตภัณฑ์บันทึกคำตัดสิน `GO` และค่า SHA-256 ของไฟล์ที่เผยแพร่ตรงกับไฟล์ที่ผ่านการยอมรับ เอกสารนี้เพียงอย่างเดียวไม่ใช่หลักฐาน `Release`

## จุดเด่น

- โปรแกรม Windows ที่คงตราสัญลักษณ์ HerdrOps แถบนำทาง แถบโครงการและสถานะ พื้นที่ทำงาน และแถบสถานะการเชื่อมต่อ ตามแบบที่อนุมัติ
- พื้นที่แดชบอร์ดสิบส่วน ครอบคลุมภาพรวม โครงสร้างทีมแบบสด กิจกรรมแบบทันที การมอบหมาย รายละเอียด Agent ความสอดคล้องของงาน กิจกรรมไฟล์ คิวตรวจสอบ การประเมิน และสรุปรายวัน
- วิดเจ็ตแบบย่อ แบบปกติ แบบขยาย แบบแจ้งเตือน แบบลอยขนาดเล็ก และแบบแนวตั้ง
- แสดงภาษาที่เลือกเพียงภาษาเดียวในแต่ละครั้ง โดยไม่ซ้อนภาษาไทยและอังกฤษในหน้าจอเดียวกัน
- ติดตาม Herdr ภายในเครื่อง พร้อมจัดการสถานะตั้งต้น เหตุการณ์ การเชื่อมต่อใหม่ และความสดของข้อมูล
- รองรับการมอบหมาย หลักฐาน การตรวจความสอดคล้อง คะแนนที่อธิบายได้ สรุปรายวัน การส่งออกภายในเครื่อง การตั้งค่า การวินิจฉัย และการกู้คืน
- ชุดไฟล์ที่รวมส่วนประกอบครบในตัวสำหรับ `win-x64` ซึ่งมี `HerdrOps.App`, `HerdrOps.Core` และ `HerdrOps.Cli` ครบ

## การติดตั้งและข้อมูล

- ระบบเป้าหมาย: Windows 11 x64
- ติดตั้งสำหรับผู้ใช้ปัจจุบันที่ `%LOCALAPPDATA%\Programs\HerdrOps`
- เก็บข้อมูลผู้ใช้ที่ `%LOCALAPPDATA%\HerdrOps`
- เมื่อลบโปรแกรม ระบบจะเก็บข้อมูลผู้ใช้ไว้ เว้นแต่ผู้ใช้ตั้งใจลบข้อมูลดังกล่าวด้วยตนเอง
- การใช้งานปกติต้องใช้บัญชีมาตรฐานที่ไม่ได้เปิดสิทธิ์ผู้ดูแลระบบ

## ข้อจำกัดที่ทราบ

- HerdrOps เป็นโปรแกรมประกอบสำหรับ Herdr ที่ติดตั้งอยู่ในเครื่อง ไม่ใช่เซิร์ฟเวอร์สำหรับทีมระยะไกล
- ชุดติดตั้งเป็นโฟลเดอร์ที่รวมส่วนประกอบครบในตัว และยังไม่อ้างว่ารองรับ MSI, MSIX, การปรับปรุงอัตโนมัติ หรือการติดตั้งสำหรับผู้ใช้ทุกคนในเครื่อง
- จะไม่อ้างว่ามีลายเซ็น Authenticode เว้นแต่มีหลักฐานลายเซ็นแนบอยู่กับรุ่นที่เผยแพร่
- ข้อมูลบางส่วนมาจากกระบวนการ ไฟล์ Git หรือการรายงานตนเองภายในเครื่อง หน้าจอต้องระบุแหล่งที่มาและความสดของข้อมูล และห้ามตีความข้อมูลอนุมานว่าเป็นข้อมูลตรงจาก Herdr
- หากสร้างไฟล์บีบอัดใหม่ ต้องถือว่าเป็นชุดเสนอเผยแพร่ใหม่ แม้ commit ต้นทางเดิม และต้องผ่านการยอมรับที่ผูกกับไฟล์ทั้งหมดอีกครั้ง

## ขอบเขตของหลักฐาน

การสร้างโปรแกรม การทดสอบด้วยข้อมูลจำลอง การตรวจสัญญา การสังเกต Herdr `Runtime` จริง การตรวจโดยผู้ตรวจอิสระ การทดสอบบนเครื่องสะอาด การอนุมัติจากผู้ใช้ และการเผยแพร่ `Release` เป็นหลักฐานคนละประเภท รุ่นเผยแพร่บน GitHub จะใช้ได้ต่อเมื่อไฟล์บีบอัดและบันทึกความถูกต้องตรงกับไฟล์ที่ผ่านการยอมรับทุกไบต์

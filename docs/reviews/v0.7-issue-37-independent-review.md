## Findings

### P1 - Missing targeted unit/integration test: apostrophe character in recovery file-system path

Scope: StateStoreRecoveryPathPolicy + StateStoreRecoveryArtifacts + StateStoreRecoveryService

Commit b6320c92 ("fix(recovery): close apostrophe path redaction leak") adds FindQuotedWindowsPathEnd
to fix apostrophe-in-path mis-termination in the diagnostic-text redactor (DiagnosticRedaction.cs)
and adds a corresponding integration test in DiagnosticBundleTests.cs that exercises apostrophes
inside quoted diagnostic attributes (e.g. diagnostic-path='"'"'C:\Users\O'"'"'Brien,...\file.cs'"'"').

However, no test in StateStoreRecoveryTests.cs or any other test file exercises a database or backup
path that contains an apostrophe character (U+0027) in a directory component, such as:

    C:\Users\O'"'"'Brien\AppData\Local\HerdrOps\state.db

StateStoreRecoveryPathPolicy.NormalizeDatabasePath calls Path.IsPathFullyQualified,
Path.GetFullPath, RejectPathSyntax, and ValidateFileName -- but none of those helpers
reject apostrophes. A path containing an apostrophe is therefore accepted and used as-is
by StateStoreRecoveryService.Restore, CreateBackup, and Quarantine.

The concern is not that apostrophes are rejected (they should be allowed -- they are legal
Windows path characters), but that the redaction layer (DiagnosticRedaction.cs) is the
only tested surface for apostrophe-bearing paths. The recovery artifact and trace paths are
not exercised end-to-end with an apostrophe-containing database path, so it is not confirmed
that recovery-trace JSON, quarantine metadata JSON, and error messages all correctly redact
(tokenise) paths when the path itself contains an apostrophe.

Specifically, the StateStoreRecoveryArtifacts.Quarantine path writes a metadata.json and
recovery-trace.json via DiagnosticBundlePublisher. The existing test
RecoveryTraceAndQuarantineMetadataTokenizePathsAndRedactFailureMessages does not use a
database path with an apostrophe, so the interaction between an apostrophe-containing
database path token and the redactor'"'"'s quoted-path boundary logic is not covered.

Actionable requirement: add at least one test in StateStoreRecoveryTests.cs that creates
a database at a path whose directory component contains an apostrophe (or simulates such
a path through StateStoreRecoveryArtifacts.Quarantine directly) and asserts that the
resulting JSON files do not contain the raw apostrophe-bearing path and do contain the
database path token.

Priority: P1 -- The apostrophe-in-path redaction fix in commit b6320c92 is the primary
safety-critical change of Issue #37, yet it has no end-to-end recovery-layer test.

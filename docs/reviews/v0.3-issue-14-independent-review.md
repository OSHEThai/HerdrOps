## Finding and remediation

Finding: P0 credential-redaction bypass.

The initial `KnownTokenPattern` covered GitHub classic token prefixes but not the fine-grained `github_pat_` prefix. A bare fine-grained PAT, including a colon-less URI user-info form such as `https://TOKEN@host`, could therefore remain in a persisted terminal or process-command summary. Existing tests used only a classic `gho_` token, so the implementation gate could pass while this leak remained.

The finding was accepted. The remediation:

- recognizes fine-grained `github_pat_` credentials;
- recognizes the current dot-separated stateless `ghs_` GitHub App token shape while retaining classic GitHub token coverage;
- redacts URI user-info with or without a separate password;
- applies through the same bounded redactor used by both terminal previews and process command metadata;
- adds required tests for a bare fine-grained PAT and its colon-less URI form;
- extends the existing token test with a stateless `ghs_` value;
- adds the new regression test to `Test-V03TerminalProcess.ps1`;
- updates the protocol contract to match the implemented protection.

GitHub's official credential reference identifies `github_pat_` as the fine-grained personal-access-token prefix. This external documentation check informed the remediation but is not runtime evidence for HerdrOps.

## Post-review CI scheduling remediation

PR #68 GitHub Actions run `31838680114` later exposed one operational failure that was not reproduced by the independent mirror: `RedactorRemovesAssignmentsAuthorizationUriCredentialsAndKnownTokens` raised `RegexMatchTimeoutException` at the first assignment-pattern pass while the hosted runner executed the solution's test projects concurrently. Contract, Integration, and Runtime suites passed in that run; Unit finished 31/32.

The failure did not persist unredacted data: timeout remains an exception and the collector fails closed. The 100 ms wall-clock ceiling was nevertheless too sensitive to hosted-runner thread scheduling. The implementation therefore raises the defensive ceiling to one second while preserving all substantive bounds reviewed above: non-backtracking regex execution, maximum 256 KiB contract input, redaction before truncation, and no fallback to unredacted text.

`RedactorScansTheMaximumContractInputAndDetectsATailSecret` now exercises an exact 256 KiB payload, places a password at its tail, requires the replacement to be observed before summary truncation, and is mandatory in the Issue #14 gate. This timeout-tolerance adjustment is controlling-run remediation evidence, not an additional independent-provider verdict.

# HerdrOps v0.4 Independent Review Record Template and Verification Guide

This document defines the canonical format for v0.4 independent review records, the structure of companion reviewed-file manifests, and the operational re-review cycle required when code changes.

---

## 1. Canonical Review Record Format

Every v0.4 independent review record (e.g. `docs/reviews/v0.4-issue-<number>-independent-review.md`) must contain the following required single-line key-value headers parsed by `tools/lib/Assert-V04ReviewBinding.ps1`:

```markdown
Verdict: PASS
CandidateCommit: <40-hex-commit-sha>
CandidateTree: <40-hex-tree-sha>
CandidateManifest: docs/reviews/v0.4-issue-<number>-reviewed-files.sha256
CandidateManifestSha256: <64-hex-sha256>
CandidateManifestEntryCount: <positive-integer>
CandidateManifestTotalLines: <non-negative-integer>
```

### Template

```markdown
# HerdrOps v0.4 Issue #<number> Independent Review Record

Reviewer: <Reviewer Name or Identifier>
ReviewedUtc: <ISO-8601 UTC Timestamp, e.g. 2026-08-22T00:00:00Z>
Verdict: PASS

CandidateCommit: <40-hex commit SHA>
CandidateTree: <40-hex tree SHA>
CandidateManifest: docs/reviews/v0.4-issue-<number>-reviewed-files.sha256
CandidateManifestSha256: <64-hex SHA-256 of the manifest file>
CandidateManifestEntryCount: <exact entry count in manifest>
CandidateManifestTotalLines: <exact sum of physical lines across all manifested files>

## Review Scope

The independent review covered the implementation and verification evidence for Issue #<number>:
- <Summary of components, contracts, tools, and tests reviewed>

## Evidence Classification

- Static Evidence: PASS
- Synthetic Evidence: PASS
- Contract Evidence: PASS
- Local SQLite Integration: PASS
- Actual Herdr Agent Runtime: NOT OBSERVED / NOT CLAIMED
- Release Acceptance: NOT CLAIMED

## Verified Evidence

1. Release build and format verification: PASS
2. Issue #<number> implementation gate: PASS
3. Full test suite: PASS

## Findings

- P0: 0
- P1: 0
- P2: 0
- P3: 0

## Evidence Boundary

This review record certifies independent audit of the exact candidate source and evidence files bound by `CandidateManifest`. It does not certify actual Herdr runtime, multi-agent execution, or release readiness.
```

## 2. Reviewed File Manifest Format

Each review record references a companion manifest file (`CandidateManifest`), typically named `docs/reviews/v0.4-issue-<number>-reviewed-files.sha256`.

### Rules
1. Every line must follow the exact format:
   ```text
   SHA256 <64-hex-sha256-uppercase> <canonical-repository-relative-path>
   ```
2. Paths must:
   - Be relative to repository root with forward slashes (`/`).
   - Not contain backslashes (`\`), parent traversal (`..`), or current directory dots (`./`).
   - Match exactly the required path set configured in `tools/Test-V04ReleaseGate.ps1` for that issue.
3. No duplicate paths or lines are allowed.
4. Line count must match `CandidateManifestEntryCount` exactly.
5. The SHA-256 of the manifest file itself must match `CandidateManifestSha256`.
6. The sum of physical lines of all manifested files must match `CandidateManifestTotalLines`.

---

## 3. Re-Review Cycle and Invalidation Policy

Review bindings in v0.4 are cryptographically bound and strictly fail-closed:

1. **Ancestor & Tree Invariants**:
   - `CandidateCommit` must be an ancestor of `CurrentHead` (`git merge-base --is-ancestor`).
   - `CandidateTree` must match `git rev-parse <CandidateCommit>^{tree}`.
2. **Blob Equality**:
   - For every manifested path, the git blob at `CurrentHead`, the git blob at `CandidateCommit`, and the working tree disk bytes must all match identically.
   - Any modification to any file in the manifest immediately invalidates the review binding.
3. **Fail-Closed Behavior**:
   - Missing review records, old-format records missing candidate fields, non-PASS verdicts (`UNAVAILABLE`, `NEEDS_CHANGES`), or hash/line/blob mismatches will cause `Assert-V04ReviewBinding.ps1` and `Test-V04ReleaseGate.ps1` to throw.

### Re-Review Steps
When implementation files are added or modified:
1. Stage and commit all changes into a clean commit on the working branch.
2. Regenerate the candidate manifest `.sha256` for the gate-required paths:
   ```powershell
   $paths = @( ... required paths ... )
   $lines = foreach ($p in $paths) {
       $hash = (Get-FileHash -LiteralPath $p -Algorithm SHA256).Hash.ToUpperInvariant()
       "SHA256 $hash $p"
   }
   $manifestText = ($lines -join "`n") + "`n"
   [IO.File]::WriteAllText($manifestPath, $manifestText, [Text.UTF8Encoding]::new($false))
   ```
3. Compute manifest metrics:
   - `CandidateCommit`: `(& git rev-parse HEAD).Trim()`
   - `CandidateTree`: `(& git rev-parse HEAD^{tree}).Trim()`
   - `CandidateManifestSha256`: `(Get-FileHash $manifestPath -Algorithm SHA256).Hash.ToUpperInvariant()`
   - `CandidateManifestEntryCount`: number of entries
   - `CandidateManifestTotalLines`: sum of physical line counts across all manifested files
4. Update `docs/reviews/v0.4-issue-<number>-independent-review.md` with the new candidate values and review findings.
5. Verify binding locally with `tools/Test-V04ReviewBinding.ps1`.

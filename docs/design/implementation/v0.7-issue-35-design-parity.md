## Required shared contracts

### Brand and wordmark

The shell must preserve the blue circular HerdrOps mark and the white `HerdrOps` wordmark as one approved visual relationship. The current prototype surface uses the approved reference crop `ApprovedOverviewReference.png` for `WideBrandMark` and `CompactBrandMark`; it does not authorize a replacement symbol, an `H`, a generic pulse icon, or an uppercase-only `HERDROPS` literal. A production brand master remains subject to the approval rule in `Plan/DESIGN-CONTRACT.md`.

### Language mode

Thai and English are complete, separate UI modes. `UiLanguageService` must expose the same key set in both catalogs, and shell/page/widget labels must bind to the selected catalog. A selected mode must not stack the other language. Product names, Agent names, identifiers, paths and protocol values remain data and are not translated.

### Status semantics

The single shared workflow vocabulary is `Working`, `Idle`, `Blocked`, `Review`, `Done` and `Offline/Unknown`. Their visual roles are green, amber, red/coral, purple, blue and slate gray respectively. Severity and review workflow are separate concepts: `Blocked`, `Review`, `Suspected`, `Confirmed`, `High` and `Critical` must not be collapsed into one badge system.

### Accessibility equivalent

The static contract requires a named navigation surface, localized `AutomationProperties.Name` or `HelpText` for interactive/page-region equivalents, visible keyboard focus, and a non-interactive accessible equivalent for the Dashboard preview. These checks do not substitute for screen-reader, DPI, contrast, multi-monitor or human accessibility review on the reference host.

## Remediation record

The candidate capture gate validates decoded PNG evidence rather than compressed file size. Each capture is decoded and checked for exact dimensions, an exact decoded pixel count, a recorded decoded-pixel SHA-256, and visible non-uniform content; final verification rechecks the same values for every expected path. This permits small but valid surfaces such as the 230×220 Floating Mini Widget.

The WPF rendering test assembly is serialized because the app uses one process-wide `UiLanguageService`. Language setup, assertions and restoration for the live dashboard rendering slice now execute inside one `WpfTestHost` dispatcher action, and language assertions use values captured from the local selected catalog.

The organization hierarchy uses bounded responsive cards at 1366×768 and 1672×941. The four leader branches remain present, ListBox selection and keyboard focus remain intact, names may use intentional character ellipsis, and status text is bounded with explicit character ellipsis so it cannot overflow a card. Synthetic layout acceptance checks cover both Thai and English at both sizes. The 58 candidate captures were regenerated after this remediation; the four organization captures were visually inspected and remain candidate evidence only.

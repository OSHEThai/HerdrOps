# v0.4 Issue #18 — CLI self-report implementation record

## Outcome

The agent-facing CLI now submits one strict versioned event to Core through a bounded,
current-user Named Pipe. Core validates the task registry and owns the acceptance
sequence, correlation, source, timestamp, and event-content hash.

## Dependency boundary

```text
HerdrOps.Cli -> HerdrOps.Contracts -> Named Pipe -> HerdrOps.Core
                                                   |
                                                   +-> task registry
                                                   +-> acceptance ledger
```

`HerdrOps.Cli.csproj` has no Infrastructure reference. The repository topology test also
checks that CLI source has no SQLite provider API. Infrastructure owns the pipe server
and SQLite remains owned only by Infrastructure; the CLI cannot open or mutate it.

## Implemented controls

- Seven exact event commands with event-specific field validation.
- Strict JSON with unknown-member rejection and explicit version checks.
- 48 KiB command input and 64 KiB framed transport bounds.
- Current-Windows-user-only Named Pipe endpoints.
- Explicit same-user trust boundary; no claim of per-process authentication.
- Core-known-task admission and structured non-zero rejection.
- Monotonic Core sequence and UTC acceptance time.
- Request correlation preservation and fixed Core source identity.
- Idempotent identical retries and fail-closed event-ID content conflicts.
- Bounded in-memory acceptance ledger that rejects when full.
- Actual Core service command capable of writing a scoped acceptance trace.

## Language boundary

The CLI is a technical machine contract and uses one stable English protocol vocabulary.
It does not render a mixed Thai/English user interface. Dashboard and Widget language
mode separation remains governed by their UI catalogs and rendering tests.

# v0.1 Issue #60 — Thai and English language separation

## Decision

- Thai is the default UI language.
- The shared top bar exposes keyboard-focusable `TH` and `EN` choices.
- Shell, Overview, Widget Gallery, and all seven Widget variants display one selected language at a time.
- Product names, Agent names, task identifiers, keyboard shortcuts, and file paths remain technical data instead of being translated.
- Paired Thai headings with English subtitles are removed from v0.1 surfaces.

## Implementation contract

- `UiLanguageService` owns complete Thai and English catalogs with identical keys.
- XAML reads localized labels from the shared catalog and updates when the language changes.
- Synthetic Overview and Widget fixtures rebuild their user-facing copy for the selected language.
- Open synthetic Widget and Gallery windows refresh their state and titles after a language change.
- The existing visual tokens, keyboard focus behavior, contrast, and responsive dimensions remain unchanged.

## Automated acceptance

- Catalog keys are identical, non-empty, and English catalog values contain no Thai glyphs.
- v0.1 XAML localization keys are checked against the catalog.
- Hard-coded Thai UI attributes and paired `ThaiTitle`/`EnglishTitle` bindings are rejected.
- Actual WPF rendering switches from Thai to English and verifies that visible English mode contains no Thai copy.
- Existing DPI, clipping, accessibility, window behavior, and Widget fidelity checks continue to pass.

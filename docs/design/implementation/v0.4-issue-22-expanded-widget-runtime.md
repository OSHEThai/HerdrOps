## Outcome

The Expanded Widget now projects Agent, role, task or activity, elapsed time, and score
from the same admitted Herdr state and assignment lifecycle used by the Dashboard,
Delegation Graph, and Task Alignment. Agent and task cells are keyboard-accessible deep
links. Missing, ambiguous, role-mismatched, or provenance-mismatched inputs fail closed
instead of being presented as facts.

## Shared-state composition

```text
Herdr state -----------------------------+
                                         |
Core-accepted self-report                |
        |                                |
        v                                v
AssignmentLifecycleIngestionCoordinator  WidgetAssignmentProjector
        |                                |
        +-> deterministic replay --------+
        +-> SQLite transaction            |
        +-> Delegation Graph              +-> Expanded Widget
        +-> Task Alignment                    Agent / role / task / time / score
```

- Agent identity binds only when the lifecycle assignee ID exactly equals the admitted
  Herdr terminal ID.
- Role binds only when the lifecycle role exactly equals the admitted Herdr Agent title.
- One Agent can project at most one current task. Multiple tasks remain diagnostics only.
- Activity, elapsed time, relationship provenance, and lifecycle provenance come from
  the selected task replay; no display-only task is invented.
- A score appears only when goal, scope, and acceptance analyses all exist and bind to
  the exact lifecycle graph SHA-256. Otherwise the score remains unknown.
- Dashboard, Delegation Graph, Task Alignment, and Widget retain the same lifecycle tip.

## Interaction and language separation

- Selecting the Agent cell routes to Agent Detail with the exact terminal identity.
- Selecting the task or activity cell routes to Task Alignment only when that exact task
  is admitted. Unsupported or missing tasks cannot navigate.
- Both row actions expose localized automation names and keyboard focus.
- Thai and English surfaces are rendered independently from the selected language
  catalog. Thai mode does not display English Core, role, or activity labels; English
  mode contains no Thai interface copy.
- Product names and stable technical values such as HerdrOps, Herdr, `TASK-120`, and
  SHA-256 values do not change with language selection.

## Durable lifecycle acceptance

- `serve-self-reports --database <absolute-path>` restores the accepted-event ledger,
  maps every new Core acceptance through one coordinator, reduces the lifecycle, and
  commits the event, audit, task, relationship, and role projections transactionally.
- Persistence runs before acceptance identity becomes visible. A failed durable commit
  does not advance the Core sequence or record a successful event.
- Restart restores exact event identity, acceptance sequence, UTC time, event hash, and
  deterministic replay hash.
- `assignment-lifecycle-acceptance` binds a durable lifecycle trace to an overlapping
  exact-Herdr runtime report and requires Project Manager, Leader, Worker, and Reviewer
  identities and roles, a complete ordered lifecycle, one visible orphan, and one visible
  current-assignee mismatch.

## Evidence boundary

The unit and integration results prove contracts, deterministic projection, failure
handling, and local SQLite behavior. The PNGs prove actual WPF rendering and interaction
from a deterministic contract-backed fixture. They do not prove that four actual Herdr
Agents performed the lifecycle. The runtime command and harness are implemented but no
runtime credit is awarded until the harness runs inside an authorized Herdr environment,
binds four exact running Agent identities and roles, and produces a passing composite
report. Current-user Named Pipe isolation does not authenticate which same-user process
submitted an event. Issue #22 and the v0.4 release gate remain open until all required
runtime and independent acceptance evidence exists.

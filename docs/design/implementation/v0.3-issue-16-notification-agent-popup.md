# v0.3 Issue #16 — Notification Widget and Agent Detail Popup

The implementation follows the approved concepts in `docs/design/reference/11-widget-concepts.png` while reusing the shared dark HerdrOps surface, typography, status colors, and wordmark.

## Notification Widget

- Four visible, vertically scrollable grouped alerts fit the approved 328 × 410 window.
- A colored status icon, Agent name, redacted summary, severity, time, group count, and acknowledgement state are presented without adding a separate dashboard vocabulary.
- Clicking a row forwards its exact event/Agent route to the window host.
- The check action acknowledges the retained group through the shared live widget state.
- “View all” routes to Realtime Activity without pretending a particular event was selected.
- Acknowledged groups remain visible with reduced emphasis instead of disappearing.

## Agent Detail Popup

- The approved 340 × 448 popup continues to use the same selected Agent as Overview, Organization, and the other widgets.
- The detail action routes only when the selected terminal identifier is still present in admitted state.
- Unknown assignment, score, and history fields remain explicitly unknown rather than being synthesized.

## Language modes

Thai mode uses Thai interface copy and English mode uses English interface copy. The two modes are rendered in separate WPF captures. HerdrOps, technical identifiers, paths, Agent-provided names, and source-provided redacted summaries are treated as data and are not machine-translated.

## Evidence boundary

The Issue #16 implementation gate may pass from bounded domain tests, App integration tests, and actual WPF rendering/interaction using deterministic contract-backed fixtures. Issue acceptance and the v0.3 release gate remain pending until an authorized Herdr environment supplies end-to-end notification delivery, latency, Agent/Task correlation, and redaction evidence.

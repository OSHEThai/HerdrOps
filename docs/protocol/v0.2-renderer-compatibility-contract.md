# v0.2 Renderer Compatibility Contract

## Authority and candidate binding

The current v0.2 renderer validator admits only manifest v4 under `herdrops-v0.2-release-first-v4`, payload SHA-256 `4958E318AF4960C5BEC8B12BA69AED384236C91570BB86F872057066939ED904`, and [Issue #149 comment 5396694185](https://github.com/OSHEThai/HerdrOps/issues/149#issuecomment-5396694185). It supersedes `herdrops-v0.2-compat-v3` for all v0.2 renderer/release acceptance; package identity and unchanged pixel/performance limits remain bound to REC-ALL v2. Manifest v1-v3 cannot earn current Issue #149 closure readiness. One v4 manifest binds one exact clean source commit/tree, package identity receipt, ZIP and extracted package manifest, App/Core bytes, reference-host profile, process-wide `SoftwareOnly`, automated captures, immutable references, comparison results, automated matrices, no-soak performance samples, and role-distinct Agent review. Any missing, malformed, stale, cross-candidate, or changed binding fails closed.

The validator must invoke the package-identity validator against the exact receipt, archive, extracted package root, repository, and profile. It recomputes receipt/leaf identities and does not accept a manifest's PASS assertions as proof. Every evidence file is confined below the evidence root, rejects reparse/path escape, is held or restability-checked against time-of-check/time-of-use changes, and is read as strict bounded content. PNG validation covers the complete file structure and dimensions from the same admitted bytes rather than accepting a header alone.

## Renderer and visual acceptance

Process-wide WPF `SoftwareOnly` must be observed before the first HWND and throughout startup, capture, Dashboard/Widget lifecycle, comparison, and measurement. The renderer observations must bind the exact producer/App report and package components.

Thai and English use separate complete capture sets. References are immutable `docs/design/reference/*.png` bytes. Pixels match exactly outside masks. Masks must be a bounded one-pixel anti-aliasing set declared before capture; no post-hoc mask is allowed. Inside masks, maximum per-channel delta is 8 and changed area is at most 0.1 percent. Automated semantic, layout, glyph, clipping, status, language-separation, keyboard/UIA, contrast, text-scale, reduced-motion, and HerdrOps brand assertions must pass. Narrator, manual perception, and ProductOwner-operated display/UI steps are not v0.2 gates.

The packaged App target-observation producer is opt-in only inside the existing
authorized runtime-evidence mode. Its eleven arguments are an all-or-none set:
`--renderer-observation-pipe`, `--renderer-runtime-evidence-root`,
`--renderer-run-nonce`, `--renderer-package-identity-path`,
`--renderer-package-receipt-sha256`, `--renderer-source-commit`,
`--renderer-source-tree`, `--renderer-challenge`, `--renderer-server-pid`,
`--renderer-server-path`, and `--renderer-server-sha256`. The pipe name is exactly
`herdrops-v02-renderer-<run-nonce>`. Before starting IPC, the App reads the
canonical package receipt from one non-reparse file handle, recomputes its
canonical SHA-256, matches source commit/tree and App/Core executable hashes,
and confines capture paths below the non-reparse evidence root. Both pipe ends
are current-user-only. The client binds the OS-observed server PID and executable
path/hash and requires the one-time challenge in every request. It accepts the
eight governed requests once and in order, rejects duplicate or unknown JSON
fields, and enumerates every process-owned native HWND before allowing the first
window. Thai and English are ordered phases. The App-owned runner renders and
registers ten captures per phase with unique tokens; the producer admits only
complete same-handle PNG bytes with bound final path, stable metadata, non-reparse
parent chain, and process lifetime. The renderer pass is always `NoRuntimeCredit`.
The producer reports only bound target observations and capture identities; it
does not author Runtime, Human, Release, or issue-closure credit.

Display coverage is six agent-configured off-screen packaged-rendering viewports: 1920x1080 and 1366x768 at 100, 125, and 150 percent scaling. No physical monitor, desktop-DPI, primary-switch, unplug, power-source, or thermal change is required. Each matrix receipt is `AutomatedPackagedRendering`, repeats the exact candidate commit/tree and package-receipt canonical SHA, shares one automated session/run, and binds distinct `EvidenceOperator` and `IndependentAgentReviewer` identities. Deterministic packaged capture is closable; caller-authored Runtime and manual/physical evidence cannot substitute for this automated contract.

## Performance (no soak)

Hardware/SoftwareOnly comparison holds candidate content, workload, host, and session constant and varies renderer policy only. Each AB and BA order has one warm-up plus five measured repetitions. Raw samples and their canonical identities are mandatory and all aggregates are recomputed. Limits are CPU <=1 percent, event-to-WPF p95 <=250 ms, SoftwareOnly CPU regression <=10 percent and <=0.50 percentage point, latency regression <=10 percent, UI-stall p95 <=50 ms, and UI-stall maximum <=100 ms. A missing or invalid sample fails.

No soak field, receipt, bin, duration, power/current sample, or resource-slope soak statistic is admitted in manifest v4. The comparator remains exactly 24 automated acquisitions covering the governed AB/BA warm-up and repetitions. The unchanged 255 MiB working-set ceiling is recomputed from those bounded acquisitions under the exact profile. A missing comparator sample fails.

## Review and evidence boundary

The builder/evidence operator and independent Agent reviewer must be distinct. Agent review binds the exact candidate and rejects open High/Critical defects. ProductOwner UI/UAT, Human visual attestation, trust root, freshness, and replay-ledger inputs are neither required nor authoritative for v0.2. CI self-tests remain verifier evidence only; actual-installed-Herdr Runtime, clean-machine lifecycle, and Release are credited only by their separate exact-candidate gates. Rebuilt or changed bytes require fresh validation and Agent review.

# v0.5 Compliance Review Trace Contract

The `trace-compliance-review` CLI emits a bounded, fail-closed trace of durable
SQLite compliance-review state. The report is `Contract` plus local SQLite
`Integration`/`BuiltProcessIntegration` evidence. It is not Actual-Herdr
`Runtime` or `Release` evidence.

## Snapshot binding

The exporter opens `SqliteHerdrStateStore` before reading trace data. One
SQLite read transaction supplies the schema version, incident registrations,
validated audit history, evidence links, and retention observations. The same
active transaction is serialized through SQLite's connection-bound database
image API; `DatabaseFileSha256` and `DatabaseFileSizeBytes` identify that
snapshot image, not a hash taken from the main database file before the reads.

If snapshot serialization, snapshot hashing, schema validation, or any
row-level integrity check fails, the exporter returns its runtime-failure code
and writes no successful report. WAL writers may commit after the snapshot is
fixed; their rows are not mixed into the report.

## Process identity

`producerProcessId` is the operating-system PID of the HerdrOps trace
producer/exporter process. It is diagnostic provenance for the exporter only;
it is never a claimed Herdr, Agent, or server PID.

`RuntimeObserved` remains `false`, and the evidence boundary remains explicit:
the trace does not prove actual running Herdr Agents, UI rendering, or release
readiness. Actual Herdr runtime and Release acceptance require their separate
fresh gates and evidence.

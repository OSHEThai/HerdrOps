## Authority and scope

The approved visual reference is `docs/design/reference/10-daily-summary.png` with SHA-256
`A44CAFDFB9A8B34694B67B6AABAD86B8B65A99A8A947C7CAB83C11FE7464F693`. The reference governs the
Daily Summary hierarchy: summary cards, highlights, strengths, areas to improve, repeated issues,
recommended actions, key-events timeline, workstream summary, and the final day score.

This contract defines the deterministic, read-only aggregation that supplies that page. It does not
authorize commands, edits, review decisions, evidence-byte collection, or a connection to Herdr.
The page must preserve the shared shell and render exactly one selected UI language at a time;
Agent names, identifiers, paths, hashes, and protocol values remain literal source data.

## Input and admission contract

`DailySummarySource` is the bounded source record. Its required fields are `SourceId`, `Kind`,
`SourceHashSha256`, UTC `OccurredUtc`, `Workstream`, `Category`, `Summary`, and `IsAccepted`.
`Kind` is `ActivityEvent` or `Evidence`. `AgentId`, `TaskId`, `IssueKey`, and
`RecommendedAction` are optional and remain null when the source does not provide them.

The aggregator accepts at most 10,000 records. Required text is Unicode-normalized, non-blank,
untrimmed, free of control characters, and bounded to its field limit. Identifiers are limited to
256 characters; summaries and recommended-action text are limited to 2,048 characters.
`SourceHashSha256` must be exactly 64 hexadecimal characters and is normalized to uppercase.
Duplicate `SourceId`, unsupported `Kind`, non-UTC timestamps, invalid hashes, null records, or
invalid text fail closed with `DailySummaryAggregationException` before a snapshot is returned.

Only records with `IsAccepted = true` whose `OccurredUtc` converts to the requested `LocalDate` in
the explicitly supplied `TimeZoneInfo` enter the accepted source set. Rejected and other-day
records are excluded from every metric and cannot be used to manufacture a highlight, issue,
action, timeline entry, or workstream. The machine's local timezone is never consulted.

## Fixed denominator and empty or missing data

The accepted source set is the single fixed denominator for the complete snapshot. Every metric,
workstream, highlight, repeated-issue, recommended-action, and timeline projection uses that same
set; rejected, out-of-day, or partially observed records must not appear in a numerator or
denominator. This version emits counts, not inferred rates. A future rate must declare its
denominator explicitly and may not use the visible-page subset.

An empty accepted source set is valid. The snapshot still emits all eight fixed metric IDs with
value `0`, empty source-ID lists, empty workstreams, empty highlights, empty repeated issues,
empty recommended actions, and an empty timeline. It also emits deterministic source-set and
result hashes. Empty does not mean live, healthy, complete, or zero activity in an unobserved
source; it means no admitted source record for the requested local day.

Missing optional Agent, Task, issue, or action data remains missing and is never replaced with a
placeholder or inferred relationship. A missing upstream event/evidence record is not converted
to a zero-valued event. It must be represented by the upstream source/availability contract; the
aggregator admits only a record carrying a valid source identity hash. Missing evidence bytes and
production provenance are therefore outside this aggregation contract.

## Deterministic projections

The fixed metric IDs and meanings are:

| Metric ID | Meaning |
| --- | --- |
| `accepted-sources` | Count of accepted source records in the local day |
| `activity-events` | Accepted `ActivityEvent` records |
| `evidence-items` | Accepted `Evidence` records |
| `workstreams` | Distinct accepted workstream labels |
| `timeline-items` | Accepted records projected to the timeline |
| `highlights` | Accepted records with `IsHighlight = true` |
| `repeated-issues` | Issue keys occurring at least twice |
| `recommended-actions` | Distinct non-null recommended-action keys |

Workstreams are grouped and ordered by ordinal workstream label. Timeline entries are ordered by
UTC occurrence and then ordinal `SourceId`; their displayed local time is the explicit timezone
conversion. Highlights use the same deterministic time/ID ordering and retain their source link.
Repeated issues group by ordinal `IssueKey`, require at least two accepted local-day records,
retain all source links, and use `Multiple` when the group spans more than one workstream.
Recommended actions group by ordinal action key, retain all source links, and are emitted once per
distinct key. All source-ID lists are ordinal-sorted.

## Provenance and hash contract

Every accepted source is represented by `SourceId`, `Kind`, and `SourceHashSha256`. The
`SourceSetSha256` canonical hash includes the count and those three values in ordinal source-ID
order. The `ResultSha256` canonical hash includes the contract version, aggregator ID, local date,
timezone ID, source-set hash, accepted source references, all fixed metrics, workstreams,
highlights, repeated issues, recommended actions, and timeline fields including each source hash.
Canonical values use length-prefixed text and invariant numeric/date formatting; input order does
not affect either hash.

`SourceHashSha256` is an upstream provenance identity. This aggregator does not read or recompute
artifact bytes, and a digest-shaped fixture value is not proof that an artifact was collected.
Changing a source identity or its upstream content must produce a new source hash and therefore a
new source-set/result identity. Source links on every displayed number or group are mandatory so a
reader can trace the summary back to the admitted source records.

## Evidence boundaries

| Evidence class | This Issue #32 slice may establish | It does not establish |
| --- | --- | --- |
| Static | Contract text, source shape, parser/hash checks, reference/hash pinning | Executed product behavior |
| Synthetic | Deterministic fixture aggregation, empty-day behavior, timezone boundaries, ordering, and hash repeatability | Compatibility with an installed Herdr session or real source bytes |
| Contract | Validation of the versioned source/snapshot/hash shapes and fail-closed error behavior | End-to-end production ingestion or authorization |
| Runtime | No runtime evidence is supplied by this contract | Actual Herdr events, reconnects, live source admission, or resource measurements |
| Independent review | Separate role-distinct review when performed | Runtime or release approval by implication |
| Release | None in this slice | Packaged installation, clean-machine acceptance, human approval, or v0.6 release readiness |

Actual Herdr Runtime NOT OBSERVED. Production event/evidence ingestion, WPF rendering, live
correlation, independent acceptance, packaging, and release evidence remain separate gates. A
passing static, synthetic, or contract check must not close those boundaries or be reported as
v0.6 release completion.

## Fail-closed behavior

The production extractor opens the originally requested path once, binds the final Windows target
path to that handle, streams the executable SHA-256 and Issue #6 markers, and retains only the
bounded schema object. Runtime factory protocol and schema admission consume that same observation,
so a junction retarget or content mutation cannot occur between separate admission reads. It then
requires one unique schema start, a balanced object within 4 MiB, strict UTF-8, valid JSON, the
admitted draft/protocol/schema version, all groups and definitions above, exact definition counts,
required variants, exact raw length, and exact raw SHA-256. Contract tests retain an injected
two-stage reader solely to prove that legacy/adversarial target and byte changes still fail closed.

Missing, duplicate, truncated, oversized, malformed, unsupported, incomplete, changed-length, or
changed-hash documents return a non-compatible status. A rejected result never exports schema
bytes.

## Evidence boundary

This is `Contract` evidence from static executable bytes. The extractor does not invoke the Herdr
CLI, connect to a Named Pipe, inspect or control a session, or prove snapshot/event/reconnect
behavior. Those runtime claims remain Issue #7 gates.

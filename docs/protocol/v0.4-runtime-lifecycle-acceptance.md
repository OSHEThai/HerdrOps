# HerdrOps v0.4 runtime lifecycle acceptance contract

Issue: [#22](https://github.com/OSHEThai/HerdrOps/issues/22)

## Scope

This contract defines the composite evidence required to bind one durable assignment
lifecycle to four role-distinct Agents observed in an overlapping exact Herdr runtime.
It does not authorize Herdr session control or infer Agent identity from display order.

## Required running identities

The runtime must contain four distinct terminal IDs with four exact titles:

| Lifecycle actor | Required role title |
| --- | --- |
| Project Manager | `Project Manager` |
| Leader | `Backend Leader` |
| Worker | `Backend Worker` |
| Reviewer | `Reviewer` |

The caller supplies the four terminal IDs. Identity binding is ordinal, case-sensitive,
and exact. A missing ID, duplicate ID, missing title, duplicate role, or role mismatch
fails closed.

## Required lifecycle

For one task, accepted order must contain:

1. Project Manager assignment to Leader.
2. Leader acknowledgement.
3. Leader delegation to Worker.
4. Worker acknowledgement.
5. Worker progress.
6. Worker evidence submission.
7. Worker handoff to Reviewer.
8. Reviewer acknowledgement.

The same durable trace must also retain at least one orphan event and at least one
`actor-not-current-assignee` mismatch. Those events are evidence that invalid inputs stay
queryable without mutating the valid task tip.

## Product command

```text
HerdrOps.Core assignment-lifecycle-acceptance \
  --lifecycle-trace <json-path> \
  --herdr-runtime-report <json-path> \
  --task-id <task-id> \
  --report <json-path>
```

All inputs are bounded to 8 MiB, strict JSON, duplicate-property-free, and validated
before output replacement. The command recomputes the deterministic lifecycle graph and
final Herdr state hashes. It requires every supporting accepted event to fall inside the
time overlap between the self-report service and Herdr runtime reports.

Exit `0` means every complete-chain, exact-Agent, orphan, mismatch, hash, and overlap
check passed. Exit `2` means no runtime credit. Exit `64` means invalid command usage.

## Authorized harness

`tools/Invoke-V04LifecycleRuntimeAcceptance.ps1` is the supported evidence runner. It:

- requires `HERDR_ENV=1` and an active `HERDR_SOCKET_PATH`;
- requires a clean committed checkout and a real evidence file;
- observes an already-running Herdr session without creating, closing, or controlling
  Agent panes;
- starts bounded hidden Core state and self-report services;
- submits a fresh ten-event corpus through the built CLI;
- writes a durable SQLite lifecycle ledger;
- invokes the product composite command; and
- writes exact source and artifact hashes to a runtime gate report.

## Trust and evidence boundary

Herdr executable admission, socket binding, exact final Agent IDs and titles, accepted
event identities, deterministic hashes, durable SQLite state, and overlapping timestamps
are machine-checked. `SessionControlInvoked` must remain false. The current-user Named
Pipe prevents cross-user access but does not authenticate which process owned by the same
Windows user submitted each CLI event. Therefore the composite report proves exact active
Agent identity and role presence plus a real CLI-to-Core lifecycle exchange; it does not
prove that each named Agent process personally emitted its corresponding event.

# v0.7 Diagnostic Bundle and Crash Metadata Contract

Status: Static/Synthetic/Contract implementation for GitHub Issue #37. Actual Herdr Runtime and Release evidence are not observed.

## Purpose

This contract defines a deterministic, bounded local diagnostic bundle for v0.7. It accepts only caller-selected summaries and excerpts. It does not read the environment, files, terminals, processes, sockets, SQLite, or dump APIs.

The implementation is split between:

- `HerdrOps.Domain.Diagnostics`: versioned models, redaction, validation, canonical JSON, and SHA-256 calculation.
- `HerdrOps.Infrastructure.Diagnostics`: safe local publication into a new directory.

The implementation is intentionally independent of the recovery and SQLite storage work.

## Schema and artifacts

Every build produces exactly three UTF-8 JSON artifacts with no indentation or trailing newline:

| File | Schema | Contents |
|---|---|---|
| `payload.json` | `v0.7.diagnostic-bundle.v1` | caller-selected app/process versions, caller-supplied UTC capture time, and allowlisted diagnostic entries |
| `crash-metadata.json` | `v0.7.crash-metadata.v1` | crash summaries only |
| `manifest.json` | `v0.7.diagnostic-manifest.v1` | artifact names, byte counts, content SHA-256 values, and content byte total |

`payload.json` has exactly these top-level fields:

```text
schemaVersion, capturedAtUtc, appVersion, processVersion, entries, crashCount
```

Each entry has exactly these fields:

```text
kind, name, text, metadata
```

The allowlisted entry kinds are `application-state`, `log-excerpt`, `environment-excerpt`, `command-line`, `url`, `headers`, and `metadata`. There is no raw-environment, arbitrary-file, terminal-dump, socket-reader, or process-dump entry kind.

`crash-metadata.json` has exactly `schemaVersion` and `crashes`. Each crash record has exactly:

```text
timestampUtc, exceptionType, category, message, stackSummary, appVersion, processVersion
```

The timestamp is supplied by the caller and must already be UTC. The record contains no exception object, dump path, dump bytes, environment, terminal content, or user profile path.

## Redaction

All text, entry names, version strings, crash fields, and nested metadata string values pass through one deterministic redactor. Nested metadata is limited to null, strings, booleans, bounded numbers, UTC `DateTimeOffset`, objects with string keys, arrays, and `JsonElement` values of those same shapes.

The redactor removes:

- every configured secret value, with longest values replaced first by one bounded matcher pass;
- URL-percent-encoded and UTF-8 Base64/Base64URL forms of configured secrets;
- assignment and JSON-key values for token, secret, password, API-key, private-key, authorization, credential, connection-string, cookie, and socket-path names;
- prose forms such as `API key is ...`, `API key: ...`, `API key=...`, and whitespace-delimited credential labels,
  plus `Authorization`, `Proxy-Authorization`, cookie, API-key, bearer/basic, URL user-info, and credential query
  values;
- common GitHub, OpenAI-style, Slack, npm, PyPI, AWS access-key, JWT, and PEM private-key shapes;
- Windows and Unix user-profile paths, user-profile variables, common `herdr.sock`/pipe paths, and other local
  absolute Windows paths, including quoted or unquoted drive, UNC, `\\?\` and `\\?\UNC\` paths with apostrophes,
  commas, semicolons, spaces, and optional line/column suffixes. Windows path matching uses a bounded linear scanner
  so valid punctuation is consumed as one path and cannot leave a residual path fragment.

Sensitive metadata field names are emitted with `[REDACTED]` values. Raw environment, full terminal, dump, socket-token, and user-profile metadata field names are rejected rather than retained. Secret values are not written to a manifest; manifests contain only fixed artifact names, lengths, and hashes.

The source input is bounded before redaction. Redacted strings, crash messages, and stack summaries have separate UTF-8 limits. A redaction result never retains the original input or includes an original-content hash.

## Bounds

The default limits are:

| Limit | Default |
|---|---:|
| Diagnostic entries | 64 |
| Crash records | 8 |
| Metadata depth | 6 |
| Metadata nodes | 256 |
| Properties per metadata object | 32 |
| Items per metadata array | 32 |
| General redacted string | 8 KiB |
| Crash message | 2 KiB |
| Crash stack summary | 4 KiB |
| `payload.json` | 128 KiB |
| `crash-metadata.json` | 64 KiB |
| Complete bundle | 256 KiB |

Inputs above a configured source bound or any count/depth/node bound fail closed. The combined configured-secret
pattern is also bounded before it is compiled, and redaction performs one replacement pass rather than repeatedly
allocating a new string for each occurrence. Output above an artifact or complete-bundle bound is rejected; it is
not silently split or truncated into additional artifacts.

## Safe publication

`DiagnosticBundlePublisher` requires an existing absolute output directory. It rejects:

- relative paths, traversal, invalid or multi-component bundle names, and destinations outside the output root;
- existing reparse-point components, including a junction/symbolic-link output root;
- an existing destination bundle directory.

The publisher writes only the three fixed artifact names using `CreateNew` into a fresh temporary directory under the validated root, flushes each file, then atomically moves the temporary directory to the requested destination. A second publication to the same destination fails and cannot overwrite the first bundle.

## Evidence boundary

The implementation and focused tests provide:

- Static evidence: source and protocol schema are present and bounded.
- Synthetic evidence: deterministic redaction, canonical ordering, malformed-input rejection, and size-bound behavior use fixtures only.
- Contract evidence: the three artifact schemas, hashes, safe path policy, atomic publication, and no-overwrite behavior are tested locally.

Actual Herdr Runtime, crash collection from a live process, clean-machine installation, Release packaging, independent approval, and GitHub Issue #37 completion are not claimed by this contract.

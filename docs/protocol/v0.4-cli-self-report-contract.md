# HerdrOps v0.4 CLI self-report contract

Issue: [#18](https://github.com/OSHEThai/HerdrOps/issues/18)

## Scope

This contract defines the version 1 local command and transport boundary used by
`HerdrOps.Cli` to submit one agent self-report event to `HerdrOps.Core`. It covers
assignment, acknowledgement, delegation, progress, deviation, evidence, and handoff.

The CLI references only `HerdrOps.Contracts`. It does not reference Infrastructure,
load a SQLite provider, open the HerdrOps database, or mutate persisted state. Core is
the only process that validates task existence and assigns acceptance identity.

## Command surface

```text
HerdrOps.Cli <event-type> --input <json-path|-> [--pipe-name <name>] [--timeout-ms <100-60000>]
```

`event-type` is exactly one of:

```text
assignment
acknowledgement
delegation
progress
deviation
evidence
handoff
```

The event type comes from the command, not from the input document. Unknown commands,
duplicate options, missing values, and payloads larger than 48 KiB fail before IPC.

## Versioned input

All JSON is UTF-8, case-sensitive camel case, comment-free, and trailing-comma-free.
Unknown members fail closed. Version 1 common fields are:

| Field | Rule |
| --- | --- |
| `contractVersion` | Must equal `1` |
| `eventId` | Non-empty UUID; idempotency key |
| `taskId` | 1-64 character identifier known by Core |
| `actorId` | 1-128 character identifier |
| `actorRole` | 1-128 character technical role name |
| `occurredUtc` | Non-default timestamp with UTC offset `Z` |
| `summary` | 1-2048 trimmed, non-control characters |
| `parentEventId` | Lifecycle parent UUID when required |
| `targetAgentId` | Assignment, delegation, and handoff target |
| `progressPercent` | Integer from 0 through 100 for progress |
| `deviationReason` | Required only for deviation |
| `evidenceReference` | Required only for evidence |
| `evidenceSha256` | Exactly 64 hexadecimal characters for evidence |
| `handoffNote` | Required only for handoff |

An assignment starts a lifecycle and therefore has no parent. Every other event type
requires `parentEventId`. Fields belonging to a different event type are rejected.
Examples for every command are under [`examples/v0.4`](examples/v0.4).

## Current-user transport

- Named Pipe protocol version: `1`
- Maximum frame: 64 KiB with a four-byte little-endian length prefix
- Client source: `HerdrOps.Cli`
- Server source: `HerdrOps.Core`
- Authorization boundary: current Windows user via `PipeOptions.CurrentUserOnly`
- Default endpoint: deterministic SHA-256-derived name scoped to the current user SID
- Request shape: sequence-zero `self-report-submit`
- Response shape: `self-report-accepted` or `self-report-rejected`

One CLI invocation opens one connection, submits one event, receives one result, and
disconnects. Core rejects an unsupported protocol, wrong source, wrong message shape,
invalid payload, unknown task, capacity exhaustion, and conflicting reuse of an event ID.
Current-user isolation is the authorization boundary; this protocol does not authenticate
one process from another process already running as the same Windows user.

## Acceptance identity

For each newly accepted event, Core atomically assigns:

- `acceptedSource`: `HerdrOps.Core`
- positive monotonic `sequence`
- request-bound envelope `correlationId`
- `acceptedUtc` with UTC offset `Z`
- deterministic `eventSha256` over the strict event contract

An identical retry of an accepted event ID returns `accepted-idempotent` with the
original sequence, UTC timestamp, source, and hash. Reusing the same event ID with
different content returns `event-id-conflict` and does not advance the sequence.

Accepted response example:

```json
{"accepted":true,"code":"accepted","message":"The self-report event was accepted by Core.","eventId":"11111111-1111-1111-1111-111111111111","eventType":"assignment","taskId":"TASK-115","correlationId":"88888888-8888-8888-8888-888888888888","sequence":1,"acceptedUtc":"2026-08-15T03:00:01+00:00","acceptedSource":"HerdrOps.Core","eventSha256":"0123456789ABCDEF0123456789ABCDEF0123456789ABCDEF0123456789ABCDEF"}
```

## Structured errors and exit codes

| Exit | Meaning | Output stream |
| ---: | --- | --- |
| `0` | Core accepted the event | result JSON on stdout |
| `64` | Invalid command, option, path, or input size | client error JSON on stderr |
| `65` | Invalid strict schema or event-specific fields | client error JSON on stderr |
| `69` | Core is unavailable or times out | client error JSON on stderr |
| `70` | Core rejected the event or returned an invalid response | Core result on stdout or client error on stderr |

Invalid schema example:

```json
{"code":"invalid-schema","message":"The self-report command input is not valid strict JSON."}
```

Unknown task example:

```json
{"accepted":false,"code":"unknown-task","message":"Task 'TASK-999' is not registered by Core.","eventId":"11111111-1111-1111-1111-111111111111","eventType":"assignment","taskId":"TASK-999","correlationId":"99999999-9999-9999-9999-999999999999","sequence":null,"acceptedUtc":null,"acceptedSource":null,"eventSha256":null}
```

## Native AOT boundary

Native AOT is not enabled by this issue. The CLI currently uses Windows Named Pipes,
strict `System.Text.Json` serialization, and Windows identity APIs. AOT may be evaluated
only after publish compatibility, binary size, startup time, and steady-state memory are
measured against the normal framework-dependent build.

## Evidence boundary

Contract tests establish parser and schema behavior. Integration tests establish the
current-user pipe and in-process Core acceptance behavior. A process trace establishes
an actual built CLI-to-Core exchange on the test host. None of these proves an installed
Herdr session event, durable lifecycle persistence, dashboard rendering, independent
review, version acceptance, or release readiness.

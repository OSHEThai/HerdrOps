# HerdrOps v1.0 Issue #43 Security and Privacy Review Contract

Status: bounded preparation contract for GitHub Issue #43. This document defines a
repeatable static and local-contract review; it does not close Issue #43 or pass the
v1.0 release gate.

## Purpose and authority

Issue #43 is the v1.0 review of final storage, migration and rollback, retention,
IPC authorization intent, redaction, local privacy, and the absence of an unexpected
network listener or normal-mode elevation declaration. `Plan/` remains the product
and release-planning authority. The implementation under review is bound to the
committed source tree supplied to the gate.

The gate is fail-closed. A missing file, missing contract marker, unexpected product
declaration, failed selected test, changed commit, dirty checkout, or unclassifiable
result is a failure. A passing gate is not permission to close the GitHub issue.

## Evidence boundary

| Class | This slice may observe | This slice does not prove |
|---|---|---|
| Static | Exact repository files, source/config declarations, document markers, parseable PowerShell, and SHA-256 identities | Runtime behavior, effective Windows ACLs, or a live listener inventory |
| Contract | Versioned source/document contracts and selected local tests using temporary data, fake endpoints, or in-memory frames | Compatibility with an installed Herdr instance or cross-account runtime isolation |
| Synthetic / local integration | Supporting fixture, SQLite, bounded filesystem, and local named-pipe test behavior when explicitly listed in the report | Production data behavior, live Herdr behavior, or release acceptance |
| Runtime | `NOT OBSERVED` | Actual Herdr, installed-product, listener, process, ACL, or non-elevated-host observations |
| Independent review | `NOT OBSERVED` | Role-distinct technical review and adjudication |
| Human | `NOT OBSERVED` | Product-owner acceptance, accessibility judgement, or go/no-go approval |
| Release | `NOT OBSERVED` | Packaging, clean-machine installation, upgrade, rollback acceptance, or publication |

The gate never reads Registry, AppData, a live database, installed Herdr bytes,
processes, sockets, or host ACLs. The current-user pipe check is a source/configuration
intent check based on `.NET PipeOptions.CurrentUserOnly` and user-scoped pipe names.
It is not an OS ACL inspection and does not authenticate which same-user process sent
a message. Normal-mode Administrator non-requirement is checked only by the absence
of an elevation declaration in product source/config; non-elevated runtime proof is
`NOT OBSERVED`.

## Required review surface

### S — static schema, privacy, and security checks

1. **S-01 Schema graph and migration identity** — the supported schema version is
   explicit; migrations 1 through 4 have stable names and executable SQL; the graph
   is forward-only; migration history records script SHA-256 values; a newer schema
   fails closed; and integrity checks surround initialization/migration.
2. **S-02 Backup and rollback documentation** — existing databases are backed up
   before migration; migration SQL is transactional; explicit rollback requires a
   named backup, expected identities, and `RESTORE_STATE_STORE`; pre/post validation,
   collision-safe artifacts, and quarantine are documented.
3. **S-03 Retention contract** — managed bytes are protected by open linked reviews;
   due unprotected bytes receive a hash-bound terminal `Purged` or `AlreadyMissing`
   event; metadata, links, and audit history remain; interrupted cleanup remains
   recoverable; and the concrete v1 retention default and bounded override are
   implemented and tested below.
4. **S-04 Export contract** — only an accepted snapshot is exported; JSON, Markdown,
   and CSV remain bounded, local, atomic, and source-hash-bound; unsafe content,
   credentials, raw payloads, paths, malformed data, and publication failures reject
   the complete export.
5. **S-05 Diagnostic and secret handling** — diagnostics are caller-selected and
   allowlisted; raw environment, terminal dumps, process dumps, socket tokens, and
   user-profile paths are not admitted; configured/common credential forms use the
   centralized bounded redactor; manifests contain artifact identities only; and
   publication is create-new/atomic/no-overwrite.
6. **S-06 Pipe ACL intent/configuration** — state and self-report endpoints use
   current-user-only pipe options on both server/client sides, derive names from a
   non-reversible user-scope hash, and retain protocol/role authorization checks.
7. **S-07 Listener declarations** — product source/config contains no unexpected
   TCP/HTTP/Web listener declaration or loopback HTTP endpoint. Named Pipe server
   declarations are the explicitly documented local IPC surface.
8. **S-08 Administrator declarations** — product source/config and manifests contain
   no `requireAdministrator`, `runas`, administrator role, or equivalent elevation
   declaration. This is not a runtime elevation test.
9. **S-09 Privacy defaults and limitations** — local-only storage, sensitive input
   treatment, bounded reads, retention/redaction-before-persistence-or-export,
   optional elevated/remote/cloud exclusions, same-user limitations, and all
   unobserved evidence classes are written down.
10. **S-10 Review-gate adversarial fixtures** — comment/string exclusions, direct
    listener declarations, dynamic network P/Invoke markers, and elevation markers
    are exercised by bounded local fixtures so the static scan does not silently
    regress toward generated/comment-only matches.
11. **S-11 Review-gate process fixtures** — bounded local fixtures start real helper
    processes through the same owned invocation path used by the gate, proving
    native argument quoting, repository/artifact paths containing spaces, a bounded
    timeout with process-tree kill and reaping, and exactly-one result-file
    fail-closed behavior. These fixtures are `Synthetic` evidence for the current
    host and shell; they do not prove installed-product, runtime, or release
    behavior.

### v1 retention and privacy default

The v1 local-only default retains managed evidence bytes for 30 days from
`ObservedUtc`. A caller may provide an explicit UTC `RetainUntilUtc` override only
when it is no earlier than `ObservedUtc` and no later than `ObservedUtc + 365 days`.
Omitting the value resolves to the 30-day default. A legacy or explicit
`RetainUntilUtc` beyond `ObservedUtc + 365 days` is rejected fail-closed by
`EvidenceRetentionPolicy.ResolveRetainUntil` with an `EvidenceContractException`;
it is never silently clamped, truncated, or grandfathered. An open linked review protects
the bytes regardless of the deadline; after the review is closed and the deadline
is due, the existing hash-bound terminal retention event and recoverable cleanup
rules apply. Metadata, review links, review history, and retention history remain
after managed bytes are purged. This is a contract/default and local-test result,
not an installed-product or actual-Herdr retention observation.

### C — local contract checks

The default gate runs selected tests for state IPC, self-report framing, export
redaction/publication, terminal redaction, SQLite migration/recovery/rollback,
evidence retention, and diagnostic bundle behavior. The selection is intentionally
local and does not include any installed-Herdr runtime acceptance command.

The selected tests are supporting evidence for this preparation slice. Their class
is recorded separately from the static scan: IPC/export tests are `Contract`,
redaction/diagnostic fixture tests are `Synthetic`, and SQLite schema/recovery/
retention tests are `LocalSQLiteIntegration`. Test names or source markers alone
never substitute for a passing test run.

## Report requirements

Every report must bind the following values:

- issue `#43`, version `v1.0.0`, branch, exact candidate commit, and exact direct-parent commit;
- every reviewed file's relative path, byte length, and SHA-256;
- one PASS/FAIL result for each `S-*` and `C-*` check;
- high findings, including `NONE OBSERVED BY THIS STATIC/CONTRACT SLICE` when true;
- `Runtime`, `IndependentReview`, `Human`, and `Release` as `NOT OBSERVED / NOT CLAIMED`;
- live listener, ACL, process, Registry, AppData/live-database, Herdr, and
  non-elevated-host boundaries as `NOT OBSERVED`; and
- Issue #43 acceptance, milestone closure, and release readiness as `PENDING`.

The report must contain hashes and bounded facts only. It must never copy secret
values, raw diagnostic payloads, terminal output, credentials, or user-profile paths.

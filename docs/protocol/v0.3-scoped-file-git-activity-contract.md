# HerdrOps v0.3 Scoped File and Git Activity Contract

Status: implementation contract for GitHub Issue #15

## Authority boundary

- One existing absolute repository root is authorized explicitly.
- Every candidate path is normalized and checked with separator-aware containment.
- Every existing reparse-point component is resolved. A target outside the canonical root is blocked.
- A blocked event retains only `[blocked]` and a bounded decision code; it never retains the rejected path.
- The collector never reads file contents. File-read events require a separate admitted Agent report.

## File-system intake

- `FileSystemWatcher` observes file-name, last-write, and size changes under the authorized root.
- The queue is bounded to 4,096 events by default and drops the oldest entry under pressure.
- Duplicate operation/path events are debounced for 100 milliseconds by default with an insertion-ordered, hard-bounded index.
- `.git`, `.vs`, `artifacts`, `bin`, and `obj` directories are excluded before queueing.
- Watcher I/O or buffer failures become explicit failure observations.

## Git intake

- Git runs directly without a shell, with prompts and optional locks disabled.
- Inherited Git directory/worktree/object/config overrides are removed; system/global config is disabled.
- Repository config includes, external common directories, external object directories, and object alternates are rejected before Git starts.
- File-system monitor hooks, untracked-cache writes, maintenance, garbage collection, and submodule recursion are disabled.
- Status uses porcelain v2, NUL-delimited paths, untracked files, and ignored submodules.
- Output is bounded to 256 KiB, commands time out after five seconds, and malformed records fail closed.
- Diff preview is repository-scoped, read-only, bounded, and passed through the shared secret redactor.
- Git status and diff never mutate the repository.
- The trace command writes only its explicit report output. `RepositoryMutationInvoked=false` means the collector and Git reader invoked no source or Git mutation; it does not deny that report-file write.

## Provenance and correlation

- Every observation carries `SourceKind`, `SourceInstanceId`, `Confidence`, UTC time, sequence, and scope decision.
- Direct watcher/Git observations begin as `Observed`.
- Agent/Task fields plus the correlation evidence source and UTC evidence time are added only when one unique, recent, separator-aware working-directory context matches.
- Ambiguous, future, expired, or missing contexts leave Agent/Task null and confidence unchanged.

## Authorized runtime command

Run from an authorized Herdr pane:

```powershell
dotnet src\HerdrOps.Core\bin\Release\net10.0-windows\HerdrOps.Core.dll trace-herdr-file-git-activity `
  --repo-root Z:\HerdrOps `
  --report artifacts/runtime-evidence/v0.3.0/issue-15/file-git-activity-runtime.json `
  --seconds 120
```

The command fails closed unless `HERDR_ENV=1`, performs no session control, binds the monitor connection to the admitted executable SHA-256, and never mutates Git or repository content. While connected, it polls the admitted session's panes and derives a bounded, separator-aware correlation context from each pane's reported `CurrentDirectory`/`ForegroundCurrentDirectory`, keyed by that pane's Herdr Terminal identifier. Every authorized `FileSystemWatcher` observation is then passed through the same fail-closed `FileActivityCorrelator` used elsewhere in the product: an observation is only marked `Correlated` when exactly one recent Agent context owns its containing directory. Runtime acceptance requires all of these report fields:

- `evidenceClassification = "Runtime"`
- `runtimeObserved = true`
- `fileSystemWatcherObserved = true`
- `gitStatusObserved = true`
- `herdrAgentCorrelationObserved = true`
- `sessionControlInvoked = false`
- `repositoryMutationInvoked = false`
- at least one file-system observation with `confidence = "Correlated"`

This command captures Agent-only correlation (the Herdr pane snapshot carries no Task identifier); a `taskId` is never populated by this command's own observations. That is a narrower, honest first cut of the correlation this contract describes, not the full Agent/Task claim.

## Evidence boundary

The controlled local trace may prove actual Windows `FileSystemWatcher` events and read-only Git metadata for the authorized repository. The authorized runtime command additionally proves Agent correlation against a live admitted Herdr session's reported pane working directory. It does not prove file-read interception, Task correlation, or v0.3 release readiness. Issue #15 remains open until that runtime evidence is captured and independently reviewed.

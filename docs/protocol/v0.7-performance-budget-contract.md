# HerdrOps v0.7 Performance Budget and Non-Runtime Preparation Contract

## Purpose and Scope

This contract establishes the deterministic validation criteria, strict schema, candidate hash binding, and path protections for HerdrOps v0.7.0 performance budgets (Issue #39, Milestone 7).

Issue #39 specifies three required deliverables:
1. Performance report verifying non-functional budgets
2. 8-hour actual-Herdr runtime soak log
3. User UAT decision

This document and its companion tool `tools/Test-V07PerformanceBudgets.ps1` define the **Non-Runtime Preparation** slice. This slice provides static, contract, and synthetic verification. It does **not** execute live measurements against an installed Herdr instance, run the live 8-hour soak, execute live human UAT, or claim v0.7 release readiness.

---

## Evidence Boundaries

HerdrOps strictly separates evidence classes in accordance with `AGENTS.md` and `Plan/RELEASE-GATES.md`:

| Evidence Class | Scope in This Slice | Boundary and Exclusions |
|---|---|---|
| **Static** | Evaluated and Observed: Clean git checkout, source commit binding, candidate executable SHA-256 binding, schema contract compliance, and reparse/path safety. | Does not verify running process behavior or host operating-system scheduler state. |
| **Synthetic** | Evaluated and Observed: Deterministic `-SelfTest` fixtures, positive passing scenarios, negative boundary violations, and tamper rejection tests. | Does not substitute for real workload data or live telemetry. |
| **Contract** | Evaluated and Observed: Verification that reported performance telemetry strictly satisfies Plan-derived target thresholds or has explicit valid waivers. | Does not claim live runtime observation. |
| **Runtime** | **NOT OBSERVED / NOT CLAIMED**: Live Herdr process connection, live latency sampling, live working-set polling, and live reconnect traces. | Requires an active, installed Herdr instance on the Windows reference host. |
| **Soak** | **NOT OBSERVED / NOT CLAIMED**: Sustained 8-hour runtime execution with continuous fault observation. | Requires live multi-agent execution in an authorized session. |
| **Human UAT** | **NOT OBSERVED / PENDING**: Human user evaluation, design review, and Beta go/no-go sign-off. | Requires explicit human operator review. |
| **Release** | **NOT OBSERVED / NOT CLAIMED**: Final installer package acceptance and release gate closure. | Blocked until all v0.7 runtime, soak, UAT, and packaging gates pass. |

## Plan-Derived Target Budgets

In accordance with `Plan/RELEASE-GATES.md` (Non-functional target budgets) and `Plan/DECISIONS.md` (D-010, D-011, D-013), candidate evaluations enforce the following eight mandatory targets:

| # | Metric Name | Plan Target Ceiling | Schema Property | Unit | Violation Condition |
|---|---|---|---|---|---|
| 1 | **Core + App idle CPU** | $\le 1.0\%$ average | `Metrics.IdleCpuAveragePercent` | Percent ($0.0 - 100.0$) | $> 1.0\%$ without valid waiver |
| 2 | **Core + App idle working set** | $\le 180\text{ MB}$ ($188,743,680\text{ bytes}$) combined | `Metrics.IdleWorkingSetCombinedBytes` | Bytes (positive integer) | $> 188,743,680\text{ bytes}$ ($180\text{ MB}$) without valid waiver |
| 3 | **Widget state-delta latency** | $\text{p95} \le 250.0\text{ ms}$ | `Metrics.WidgetStateDeltaLatencyP95Ms` | Milliseconds (positive float) | $> 250.0\text{ ms}$ without valid waiver |
| 4 | **Dashboard cold launch** | $\text{p95} \le 2.0\text{ s}$ ($2000.0\text{ ms}$) | `Metrics.DashboardColdLaunchP95Ms` | Milliseconds (positive float) | $> 2000.0\text{ ms}$ without valid waiver |
| 5 | **Herdr reconnect and reconcile** | $\le 5.0\text{ s}$ ($5000.0\text{ ms}$) | `Metrics.HerdrReconnectReconcileSeconds` | Seconds (positive float) | $> 5.0\text{ s}$ without valid waiver |
| 6 | **Unbounded terminal reads** | Exactly $0$ | `Metrics.UnboundedTerminalReads` | Integer | $> 0$ without valid waiver |
| 7 | **Unhandled crash during v0.7 soak** | Exactly $0\text{ in }8\text{ hours}$ | `Metrics.UnhandledCrashesDuringSoak` | Integer count | $> 0$, or $\text{SoakDurationHours} < 8.0\text{ h}$ ($28,800\text{ s}$) for soak runs |
| 8 | **Normal-mode Administrator requirement** | None (Non-elevated) | `Metrics.AdministratorRequired` | Boolean | `true` without valid waiver |

## Strict Schema Specification (`v0.7.0`)

Performance budget evaluation reports must strictly conform to the `v0.7.0` document schema. The evaluator uses a strict JSON parser that fails closed under any of the following conditions:
1. Unrecognized top-level or nested properties (disallowed unknown properties).
2. Duplicate object keys at any nesting level.
3. `NaN`, `Infinity`, or `-Infinity` numeric values.
4. Negative numbers where positive quantities are required (e.g. latency, bytes, durations, counts).
5. Percentages outside the valid range $[0.0, 100.0]$.
6. Timestamps that are not ISO 8601 UTC strings ending with `Z`.
7. Schema version string other than `"v0.7.0"`.

## Waiver Rules and Schema

`Plan/RELEASE-GATES.md` stipulates:
> *"If a target cannot be met, the release requires a recorded measurement, cause, impact and explicit waiver. Changing a target does not retroactively turn a failed run into a pass."*

When a reported metric exceeds its target, the evaluator marks that metric as `FAIL` unless an exact, valid, and fully-formed waiver is supplied within `Waivers[]`.

Each waiver object must satisfy:
1. `Metric`: Exact metric key string matching one of the eight defined metrics.
2. `Target`: Target ceiling description (e.g. `"<= 1.0%"`).
3. `Observed`: Recorded failing value as a string.
4. `Cause`: Non-empty string detailing the technical root cause.
5. `Impact`: Non-empty string detailing user and operational impact analysis.
6. `ApprovedBy`: Non-empty string identifying the authorized human approver (e.g. `"@yutthaphon"`).
7. `ApprovalDateUtc`: ISO 8601 UTC timestamp of approval.
8. `ApprovalReference`: Exactly `Plan/RELEASE-GATES.md#v07-performance-waiver-authority`.
9. `WaiverSha256`: Lowercase hex SHA-256 hash computed over the canonical UTF-8 representation of the waiver fields (`Metric:Target:Observed:Cause:Impact:ApprovedBy:ApprovalDateUtc:ApprovalReference`).

A valid waiver transitions the metric status from `FAIL` to `PASS (WAIVED)`. The gate report explicitly records every waiver and its provenance.

## Candidate and Source Hash Binding

To ensure artifact provenance and prevent stale or manipulated inputs:
1. **Source Commit**: Evaluator resolves `git rev-parse --verify HEAD^{commit}` and checks `git status --porcelain=v1 --untracked-files=all`. Any uncommitted change or dirty working tree causes immediate failure.
2. **Candidate Binaries**: For non-runtime Preparation, if `Candidate.Binaries` is declared, every entry must be independently verified on disk for exact path containment, byte length, and SHA-256; missing roots, missing files, or mismatches fail closed and no entry may be reported as bound when verification is skipped. Runtime admission is stricter: Core and App ProcessTelemetry paths and SHA-256 values must match the role-specific declared candidate binaries, and both binaries must be independently verified on disk for exact length and SHA-256.
3. **Immutability**: Rebuilt binaries require a fresh evaluation run even when source code is unchanged.

---

## Path, Traversal, and Reparse Protections

1. **Path Containment**: All evaluated paths (candidate binaries, reports, fixtures, output directories) must resolve strictly within the designated repository root or artifact directory. Paths containing `..` or leading outside the root are rejected.
2. **Reparse Point (Junction / Symlink) Defense**: Evaluator verifies filesystem attributes using `[IO.File]::GetAttributes()`. Any path exhibiting `[IO.FileAttributes]::ReparsePoint` targeting an external or unauthorized directory is rejected immediately.
   The check walks every existing ancestor from the evaluated leaf to the repository boundary; a clean leaf does not override a reparse-point parent.
3. **Bounded I/O**: File reading enforces a maximum file size bound ($4\text{ MiB}$ for JSON reports), maximum line count limits, and safe UTF-8 decoding without unhandled BOM anomalies.

Runtime admission additionally requires exact Core/App process identities with positive PIDs, valid UTC start timestamps, stable PID/start-time pairs, distinct role-specific binaries with actual path/length/SHA-256 binding, non-empty raw latency and launch samples whose p95 values are recomputed, and both `ActualHerdrRuntime` and `SoakExecution` equal to `OBSERVED`. Preparation reports—including zero, partial, or numerically complete synthetic soak fields—remain `NOT OBSERVED` and cannot satisfy the 8-hour runtime gate. Waivers fail closed unless `ApprovedBy` is the Plan-authorized identity and `ApprovalReference` points to the Plan authority record, with a valid non-future UTC approval timestamp and matching canonical SHA-256 binding.

# v0.2 automated release-artifact production contract

This contract implements D-026 through D-028 for Issues #11 and #149. It produces evidence and readiness reports only. It never closes GitHub objects, tags a commit, publishes a package or creates a Release.

## Governed evidence receipts

Run `tools/v0.2-release/Invoke-V02ReleaseEvidencePublisher.ps1` once for each class from a clean exact candidate. Contract is exactly `installed-herdr-protocol-contract` plus `bundled-schema-contract`. Synthetic is exactly `live-pages-packaged-rendering`, `live-widgets-packaged-rendering` plus `thai-english-language-modes`. Schema v2 binds the exact commit/tree, PASS exit status, transcript path and SHA-256. Runtime, actual-Herdr and Release flags are false.

Each class uses a new direct child directory of the explicit evidence root, for example `contract/receipt.json` and `synthetic/receipt.json`. All checks finish successfully before any transcript is staged. Publication holds the root, transaction parent, governed scripts and staging identity, then exposes the complete receipt/transcript set with one root-relative held-handle directory rename. A failed check exposes no partial set. Existing destinations, path escape, swaps and reparse ancestry fail closed.

## Authenticated GitHub snapshots

`New-V02AuthenticatedGitHubSnapshot.ps1` calls `https://api.github.com` with a bearer token read from `GH_TOKEN` (or the explicitly named environment variable). The token is never serialized. Schema v3 contains the exact candidate, the successful `build-test` check, milestone #2 and the exact issue set 6, 7, 8, 9, 10, 11, 54, 63 and 149.

`Preclosure` requires milestone #2 open, #11/#149 open and every other listed issue closed. `FinalClosure` requires the milestone and every listed issue closed and binds `preclosureSnapshotSha256`. ReleaseGate repeats the authenticated API calls and compares the live state with the supplied snapshot.

## Independent Agent review

The independent Agent writes canonical JCS-plus-LF schema-v1 `IndependentAgentReviewResult` JSON outside the repository/evidence root. It contains exact properties `SchemaVersion`, `EvidenceClass`, `DecisionId`, `Candidate`, `Builder`, `IndependentReviewer`, `Decision`, `Findings` and `EvidenceBoundary`; each finding has exact `Id`, `Severity`, `Status`, `Summary`. The publisher derives both roles from this document and rejects candidate drift, role/task collision, invalid decision/boundary or any open High/Critical defect before posting. It then uses the owner-authorized GitHub token to post one exact marker-plus-JCS Issue #149 comment. Schema-v4 receipt captures the comment and structured-result binding. No caller-supplied role strings, additional GitHub account, private key or manual ProductOwner action is required.

The candidate lock is schema v3. `New-V02ApprovedCandidateLock.ps1` deterministically copies all reviewed candidate hashes, the preclosure snapshot hash, exact D-026 authority bytes and the external receipt, review-result and GitHub comment bindings. Both external files must resolve below `ExternalReviewRoot` and outside the repository and release-evidence roots. The lock grants neither Runtime nor Release credit.

## Execution order

1. Build/package and collect renderer, runtime matrix, Issue #9, lifecycle and language evidence for one clean exact candidate.
2. Publish governed Contract and Synthetic receipts.
3. Close implementation issues other than #11/#149; publish the authenticated `Preclosure` snapshot.
4. Obtain the role-distinct internal Agent result; let the owner-authorized automation post its exact GitHub comment and publish the external review receipt outside both repository and evidence root.
5. Publish the candidate lock inside the evidence root.
6. Run ReleaseGate with `-ReleasePhase Preclosure`. It must report `READY_FOR_GITHUB_CLOSURE`, `ClosureReady=true`, `ReleaseReady=false`.
7. Close #11/#149 and milestone #2 through the separately authorized GitHub workflow. Publish `FinalClosure` using the retained preclosure snapshot.
8. Rerun the same gate and candidate with `-ReleasePhase FinalClosure`. A pass means ready-not-published only.

Every production invocation uses a clean `powershell` or `pwsh` process and explicit absolute evidence paths. The independent receipt must remain outside the repository and evidence root.

## Executable command skeleton

The following variables come from the already validated package/runtime chain. `review-external` must be outside both the repository and `evidence`.

```powershell
$repo = 'Z:\HerdrOps'
$evidence = 'D:\HerdrOpsEvidence\v0.2\candidate'
$reviewExternal = 'D:\HerdrOpsIndependentReview\v0.2'
$commit = git -C $repo rev-parse HEAD
$tree = git -C $repo rev-parse 'HEAD^{tree}'

pwsh -NoProfile -NonInteractive -File "$repo\tools\v0.2-release\Invoke-V02ReleaseEvidencePublisher.ps1" `
  -EvidenceClass Contract -ExpectedSourceCommit $commit -ExpectedSourceTree $tree `
  -RepositoryRoot $repo -EvidenceRoot $evidence -OutputPath "$evidence\contract\receipt.json"
pwsh -NoProfile -NonInteractive -File "$repo\tools\v0.2-release\Invoke-V02ReleaseEvidencePublisher.ps1" `
  -EvidenceClass Synthetic -ExpectedSourceCommit $commit -ExpectedSourceTree $tree `
  -RepositoryRoot $repo -EvidenceRoot $evidence -OutputPath "$evidence\synthetic\receipt.json"

pwsh -NoProfile -NonInteractive -File "$repo\tools\v0.2-release\New-V02AuthenticatedGitHubSnapshot.ps1" `
  -Phase Preclosure -ExpectedSourceCommit $commit -ExpectedSourceTree $tree `
  -EvidenceRoot $evidence -OutputPath "$evidence\github-preclosure.json" -GitHubTokenEnvironmentVariable GH_TOKEN

pwsh -NoProfile -NonInteractive -File "$repo\tools\v0.2-release\New-V02IndependentAgentReviewReceipt.ps1" `
  -ExpectedSourceCommit $commit -ExpectedSourceTree $tree `
  -ProfileFileSha256 $profileFileSha -ProfileCanonicalSha256 $profileCanonicalSha `
  -PackageReceiptSha256 $packageReceiptPayloadSha -PackageReceiptFileSha256 $packageReceiptFileSha `
  -PackageArchiveSha256 $archiveSha -PackageManifestSha256 $manifestSha `
  -PackageAppSha256 $appSha -PackageCoreSha256 $coreSha `
  -RendererManifestSha256 $rendererSha -RuntimeMatrixManifestSha256 $matrixSha `
  -Issue9CandidateSha256 $issue9Sha -PreclosureGitHubSnapshotPath "$evidence\github-preclosure.json" `
  -AuthorityReferencePath "$repo\Plan\DECISIONS.md" `
  -ReviewResultPath "$reviewExternal\reviewer-result.json" `
  -RepositoryRoot $repo -EvidenceRoot $evidence -ExternalOutputRoot $reviewExternal `
  -OutputPath "$reviewExternal\independent-agent-review.json" `
  -GitHubTokenEnvironmentVariable GH_TOKEN -PublishGitHubComment

pwsh -NoProfile -NonInteractive -File "$repo\tools\v0.2-release\New-V02ApprovedCandidateLock.ps1" `
  -IndependentCandidateReceiptPath "$reviewExternal\independent-agent-review.json" `
  -PreclosureGitHubSnapshotPath "$evidence\github-preclosure.json" `
  -AuthorityReferencePath "$repo\Plan\DECISIONS.md" -RepositoryRoot $repo `
  -EvidenceRoot $evidence -ExternalReviewRoot $reviewExternal `
  -OutputPath "$evidence\candidate-lock.json"
```

Invoke `tools/Test-V02ReleaseGate.ps1` directly with every mandatory package, renderer, Thai/English runtime, matrix, Issue #9, Contract, Synthetic, lifecycle, authority, review, lock and evidence-root path. For the first run add `-ReleasePhase Preclosure -GitHubSnapshotPath "$evidence\github-preclosure.json"`; `-PreclosureGitHubSnapshotPath` may be omitted because it is the same file. After automated GitHub closure, publish final state and rerun:

```powershell
pwsh -NoProfile -NonInteractive -File "$repo\tools\v0.2-release\New-V02AuthenticatedGitHubSnapshot.ps1" `
  -Phase FinalClosure -ExpectedSourceCommit $commit -ExpectedSourceTree $tree `
  -PreclosureSnapshotPath "$evidence\github-preclosure.json" -EvidenceRoot $evidence `
  -OutputPath "$evidence\github-final-closure.json" -GitHubTokenEnvironmentVariable GH_TOKEN
```

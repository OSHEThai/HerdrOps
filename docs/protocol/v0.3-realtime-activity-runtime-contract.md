# v0.3 Realtime Activity Runtime Contract — Issue #13

## Status

Implementation and operator-capture contract for GitHub Issue #13. The command is
fail-closed outside an authorized Herdr pane and does not itself create an Agent
transition. Contract, synthetic, and WPF evidence remain separate from the actual
runtime report.

## Authorized command

From a clean committed checkout, build the Release Core binary and run this command
from an authorized Herdr pane:

```powershell
dotnet artifacts/bin/HerdrOps.Core/release/HerdrOps.Core.dll trace-herdr-realtime-activity `
  --report artifacts/runtime-evidence/v0.3.0/issue-13/realtime-activity-runtime.json `
  --seconds 120
```

During the bounded window, the operator must cause at least one real admitted
`pane.agent_status_changed` transition. The command binds the monitor to the exact
admitted Herdr executable SHA-256, routes the accepted transition into the v0.3
`ActivityEventPipeline`, flushes bounded debounced state before writing the report,
and never invokes Herdr session control.

Runtime acceptance requires all of these report fields:

- `evidenceClassification = "Runtime"`
- `runtimeObserved = true`
- `activityEventObserved = true`
- `activityEmissionObserved = true`
- `sessionControlInvoked = false`
- `admission.executableSha256` matches the verified control session
- `monitorServerIdentity.executableSha256` matches the same admitted executable
- at least one event has an activity identity/envelope SHA-256 and measured latency

## Evidence boundary

The report proves only that an accepted live Herdr Agent-status transition reached
the v0.3 activity pipeline and produced a bounded emission for one admitted session.
It does not prove Task correlation, notification delivery, restart persistence,
independent review, or v0.3 release readiness. The report must be independently
reviewed and bound to the exact clean source commit before Issue #13 or tracker #17
can receive acceptance credit.

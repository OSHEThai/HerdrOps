platform branch. The installed integration source embedded in the executable constructs a
Windows Named Pipe path from `HERDR_SOCKET_PATH`.

## Fail-closed policy

HerdrOps accepts only the exact release ID and binary SHA-256 listed above. A changed release,
changed hash, malformed PE header, unreadable file, missing RPC method, missing shape, or missing
transport marker returns a non-compatible result. The command exits with code `2` for
compatibility failures and code `64` for invalid command usage.

The 0.8.2 admission is a reviewed successor contract, not compatibility inferred from a
semantically similar version string. Any later binary still requires another successor contract
and fresh inspection.

## Evidence boundary

The installed-binary inspection is `Contract` evidence. It scans executable bytes from one
final-path-bound handle without retaining an executable-sized managed image and does
not invoke the Herdr session-control CLI. It does not prove a live Named Pipe connection, actual
snapshot/event payloads, state semantics, disconnect/reconnect, reconciliation, or release
readiness. Those are version-local runtime gates for Issues #7–#10.

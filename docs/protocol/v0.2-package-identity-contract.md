This contract implements Issue #149 package-identity preparation under `herdrops-rec-all-v2` ([authoritative owner record](https://github.com/OSHEThai/HerdrOps/issues/149#issuecomment-5380637664)), canonical payload SHA-256 `48474610D2A20EE2F7CA2DAC0A3CCF45F919440C9C5D81EF5BA93AD7E524F62D`. The superseded `herdrops-rec-all-v1` record and payload SHA-256 `DD8EB4D4BC896BE6A4765D409C5E34A16C4DBFB3D70F437EC915A50DF2FC1B1E` must be rejected. The governed v0.2 reference-host profile SHA-256 is `96D01ED15A536F2DF50B59B43CFDEB3683DCE8667AE2E7BF6A96124182FE13A3`, the renderer-policy SHA-256 is `1D37C9C39449556EB30F9AB5B734F0C5411CF4203321AF0B238993D017229E92`, and the package-receipt-schema SHA-256 is `8C7EF64ED06C94C6589D73C0AB47EB60B7EEF7BFE337F126D8D9D3F0CC0F4C4B`. Any authority or hash substitution fails closed.

The selected distribution is a self-contained `win-x64` ZIP plus a PowerShell per-user installer. Startup is opt-in, uninstall retains user data, and there is no auto-update. An unsigned local package plus SHA-256 is acceptable only for bounded local distribution. A future signing decision requires controlled-certificate authority and fresh evidence for the exact signed artifact.

## Atomic identity

`tools/packaging/v0.2/Test-V02PackageIdentity.ps1` validates an identity request against one held artifact set and emits the canonical atomic receipt identity. Admission requires:

- a clean source repository before and after validation, exact 40-hex commit and tree, and no substitution through untracked or reparse paths;
- the canonical preparation profile, exact package-receipt schema SHA-256, strict UTF-8/JCS identity, known `herdrops-rec-all-v2` authority, exact reference-host profile, and process-wide `SoftwareOnly` renderer policy with its exact policy SHA-256;
- a valid ZIP whose exact bytes and SHA-256 match the receipt, whose extracted root matches the archive, and whose canonical package manifest binds the complete file set without duplicates, aliases, traversal, or unlisted bytes;
- exact relative paths, lengths, and SHA-256 values for `HerdrOps.App.exe`, `HerdrOps.Core.exe`, the package manifest, preparation profile, and archive; and
- same-handle/stable-byte validation across reads, with any dirty-source, identity drift, time-of-check/time-of-use change, malformed JSON, unknown field, missing file, hash/length mismatch, reparse point, or path escape failing closed.

The receipt SHA-256, profile identity, source commit/tree, archive identity, package-manifest identity, App/Core identities, reference-host profile, and renderer-policy identity form one indivisible handoff. Changing or rebuilding any bound byte requires a new receipt and all downstream evidence must bind the successor.

## Evidence boundary

Verifier self-tests use isolated fixture repositories and synthetic ZIP bytes. Their PASS is Static, Contract, and Synthetic verifier evidence only. An identity receipt is `PackagedCompatibilityPreparation`; it does not establish a real package build, installer behavior, clean-machine installation, actual Herdr Runtime, accessibility, performance/soak, Human GO, Release, signing, tag, or publication. Issues #10 and #149 remain open until their version-local acceptance and issue-local evidence are complete.

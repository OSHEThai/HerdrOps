# v0.5 Compliance Diagnostic Export Contract — Issue #28 T4

Status: local Static/Synthetic/Contract/Integration implementation. Actual Herdr Runtime,
installed-product acceptance, Release packaging, and v0.5 completion are not observed.

## Boundary

`HerdrOps.Cli` submits a bounded request over a current-user-only Named Pipe to
`HerdrOps.Core`. Core owns validation, deterministic serialization, and file publication.
The direct Core command uses the same exporter for fixture and contract tests:

```text
HerdrOps.Core compliance-diagnostic-export --input <json-path> --output <absolute-json-path>
HerdrOps.Core serve-compliance-diagnostic-export [--pipe-name <name>] [--seconds <1-3600>]
HerdrOps.Cli compliance-diagnostic-export --input <json-path|-> --output <absolute-json-path>
```

The exporter accepts a caller-selected normalized snapshot. It does not read Herdr,
SQLite, terminals, processes, environment variables, arbitrary files, or evidence bytes.
The export is diagnostic metadata only and cannot be used as Runtime or Release evidence.

## Input allowlist

Input schema is `v0.5.compliance-diagnostic-input.v1`. Its only fields are:

```text
schemaVersion, generatedUtc, records
record: incidentId, incidentState, registeredUtc, updatedUtc,
        registrationSha256, review, evidence
review: reviewId, state, updatedUtc, auditSha256
evidence: evidenceId, state, observedUtc, metadataSha256, contentSha256
```

Incident IDs and review-case IDs are bounded canonical identifiers. Evidence IDs and
every SHA field are exactly 64 hexadecimal characters and are
normalized to uppercase. States are closed enums from the existing compliance/evidence
contracts: incident `Suspected`, `PendingLeader`, `PendingProjectManager`, `Confirmed`,
or `Dismissed`; review `Open` or `Closed`; evidence `Present` or `Missing`. Timestamps
are canonical UTC values with seven fractional digits.

Unknown members, duplicate members, numeric enum values, malformed IDs/hashes/timestamps,
duplicate incident/review/evidence IDs, inconsistent missing/present hashes, and
secret-bearing/path/free-text members fail closed before publication. The output has no
field capable of carrying a password, token, local path, actor, task, source reference,
reason, prose, terminal text, or arbitrary metadata. Rejecting these fields is the
redaction boundary: no rejected value is copied to output or returned in an error.

## Exact output and bounds

Output is one compact UTF-8 JSON file with no BOM, no trailing newline, and schema
`v0.5.compliance-diagnostic-export.v1`:

```text
schemaVersion, generatedUtc, recordCount, records
```

Records and evidence are sorted by their canonical IDs. The default limits are:

| Limit | Value |
|---|---:|
| Input bytes | 512 KiB |
| Records | 256 |
| Evidence per record | 256 |
| Total evidence | 4096 |
| Output bytes | 256 KiB |
| IPC frame bytes | 768 KiB |

An input or output above a bound is rejected; it is never truncated or split. The SHA-256
returned by Core/CLI is the hash of the exact published UTF-8 output bytes.

## Safe publication

Core requires an absolute `.json` output path with no `.`/`..` segment, an existing
non-reparse parent chain, and a destination that does not already exist. It writes one
uniquely named sibling temporary file with `CreateNew`, flushes it to disk, and moves it
to the final name with overwrite disabled. A collision or publication error leaves no
accepted output and cannot replace the existing destination. A concurrent same-user
filesystem reparse swap remains an OS/filesystem trust-boundary residual; the observed
path is inspected immediately before staging and publication.

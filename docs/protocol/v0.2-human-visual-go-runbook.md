# v0.2 final Human visual-GO candidate and attestation runbook

This runbook covers Issues #11 and #149. It defines a candidate hand-off, not a
release action. The builder may create only a `HumanReviewCandidate`; it may
not write a Human decision, ProductOwner authority, Runtime result, Release
result, tag, package publication, or GitHub state.

## Required inputs

The renderer manifest must be validated with the existing packaged
compatibility verifier against one clean exact candidate. The candidate must
bind:

- the exact source commit/tree, package profile and receipt, ZIP, package
  manifest, App and Core bytes, governed Herdr identity from
  `Plan/reference-hosts/v0.2.json`, session identity, and SoftwareOnly policy;
- all 20 governed captures (ten Thai and ten English), all 11 immutable
  reference PNGs, every predeclared mask and its mask-set receipt;
- every renderer proof and producer receipt, every observed display/mixed-DPI/
  accessibility/environment matrix receipt, and the complete performance
  receipt including raw AB/BA samples and 24 AC/battery soak bins; and
- the separate `human-visual-review-evidence.schema.json` record, held under
  the evidence root, bound to the renderer manifest/source and containing all
  20 comparison dispositions, seven visual checks, and every defect
  disposition. This record is evidence only; it is not Human authority.

All input bytes are pinned from held handles before validation. The existing
renderer verifier requires its own exclusive readers, so the gate releases
only those OS handles while retaining the pinned byte snapshots, runs the
renderer checks, then reacquires and rechecks every path by final handle path,
file identity, length, and same-handle bytes. It rejects reparse points, path
escape, hardlink/file-identity aliases, final-handle path changes, byte drift,
concurrent output, and evidence exceeding the bounded held-file/total size.

## Candidate generation

Run the builder from the exact clean candidate checkout. The output path must
be outside both the repository and evidence root and must not already exist:

```powershell
./tools/v0.2-human-visual-go/New-V02HumanReviewCandidate.ps1 `
  -RendererManifestPath <evidence-root>/renderer-compatibility.json `
  -HumanReviewEvidencePath <evidence-root>/human-review/visual-review-evidence.json `
  -EvidenceRoot <evidence-root> `
  -RepositoryRoot Z:\HerdrOps `
  -BuilderIdentity <builder-identity> `
  -RuntimeOperatorIdentity <runtime-operator-identity> `
  -IndependentValidatorIdentity <independent-validator-identity> `
  -OutputPath <external-root>/HumanReviewCandidate.json
```

The generated JSON uses
`tools/v0.2-human-visual-go/human-review-candidate.schema.json`. Its boundary
is always `humanReview=NOT_OBSERVED`, `actualHerdrRuntime=NOT_OBSERVED`,
`release=NOT_OBSERVED`, and `creditGranted=false`.

## External attestation

The authorized reviewer supplies a separate, candidate-specific JSON document
using `human-go-attestation.schema.json`. It must remain outside the
repository and evidence root. It must contain:

- `decision` exactly `GO` or `NO_GO` and canonical `reviewedUtc`;
- reviewer `@yutthaphon`, role `HumanReviewer`, authority role `ProductOwner`,
  and identities distinct from builder, Runtime operator, and independent
  validator;
- an external HTTPS authority reference, authentication method, authenticated
  flag, and nonzero proof hash;
- candidate file/canonical hashes, source commit/tree, App/Core/archive/Herdr/
  session bindings, the complete evidence-binding array and its set hash;
- every visual comparison disposition and every candidate defect ID,
  severity, status, and disposition; and
- every governed visual check, including accessibility/Narrator coverage
  represented by the matrix and visual-check receipts; and
- `actualHerdrRuntime=NOT_OBSERVED`, `release=NOT_OBSERVED`, and
  `creditGranted=false`.

The repository cannot supply or pin that authority. A copied, stale, forged,
aliased, mixed-candidate, incomplete, or locally referenced attestation fails
closed. `GO` is accepted only when all required visual, matrix, performance,
soak, accessibility, and defect gates are complete and passing. A valid Human
GO still does not grant Release.

Verify the hand-off without contacting GitHub or starting Herdr:

```powershell
./tools/v0.2-human-visual-go/Test-V02HumanVisualGoAttestation.ps1 `
  -CandidatePath <external-root>/HumanReviewCandidate.json `
  -AttestationPath <external-root>/HumanVisualGoAttestation.json `
  -EvidenceRoot <evidence-root> `
  -RepositoryRoot Z:\HerdrOps
```

Omitting `-AttestationPath` deliberately returns a candidate-only
`NOT_OBSERVED` result. Supplying a valid external attestation returns its
`GO`/`NO_GO` decision as a validated Human-review input while retaining the
Runtime/Release boundary.

## Evidence class and CI

The self-test is `Synthetic` verifier evidence. Run it once in PowerShell 7
and once in Windows PowerShell 5.1:

```powershell
./tools/v0.2-human-visual-go/Test-V02HumanVisualGoAttestation.SelfTests.ps1
powershell.exe -NoLogo -NoProfile -NonInteractive -ExecutionPolicy Bypass `
  -File .\tools\v0.2-human-visual-go\Test-V02HumanVisualGoAttestation.SelfTests.ps1
```

These checks do not observe an installed Herdr instance, do not perform a
Human interaction, do not grant Runtime or Release credit, and do not mutate
GitHub.

# v1.0 Issue #41 Dependency Audit Contract

Status: non-runtime preparation only.

This contract defines the fail-closed audit used by Issue #41, `[v1.0.0] Close release blockers and audit all dependency evidence`. It audits the required GitHub issues in milestones `v0.1.0` through `v0.7.0`, their release trackers, and the local version-gate bindings. It does not close issues, freeze a release candidate, publish a package, or perform runtime acceptance.

## Sources of truth

The audit reads these committed files from the checkout being audited:

- `Plan/github-roadmap.json` supplies version-local issue keys and canonical issue titles.
- `Plan/GITHUB-TRACKING.md` supplies the milestone number, work-issue count, and release-tracker issue for each version.
- `Plan/RELEASE-GATES.md` supplies the evidence-class and version-gate policy.

The GitHub query must contain exactly one record per issue number and milestone number/title. Every array endpoint is read through bounded pagination with a maximum page size of 100. Issues use stable ascending creation order so records beyond the first 100 cannot disappear when newer issues or pull requests exist; milestones use the API-supported ascending `due_on` order. Every page is strict JSON, and the report binds each page endpoint and response SHA-256. A full final page at the bounded page limit fails closed instead of assuming completeness. Pull requests returned by the GitHub Issues API are rejected as duplicate/invalid input rather than silently becoming dependencies. A work issue present in a milestone but not represented in `github-roadmap.json` is retained as a required supplemental milestone issue; it is never silently dropped. The shared `tools/Test-VersionMilestone.ps1` verifier uses the same bounded pagination policy, matches the selected milestone title case-sensitively, and validates every returned issue milestone number/title pair against the declared milestone before counting open or closed version issues; a first-page-only or number-only result is not release evidence.

For each dependency version, the output maps every issue to:

- the GitHub issue number, title, state, milestone and URL;
- the local release tracker from `Plan/GITHUB-TRACKING.md`;
- `tools/Test-VersionMilestone.ps1`, `Plan/RELEASE-GATES.md`, and the version-specific local gate scripts;
- the exact audit source commit and Plan-file hashes.

The v1.0 issues are not pre-v1 dependencies. Issue #41 itself is checked as the target issue; issues #42–#46 are not included in the pre-v1 dependency set.

## Evidence classes

Every evidence entry contains all of these keys, even when the status is `NOT_OBSERVED`:

`Static`, `Synthetic`, `Contract`, `Integration`, `Runtime`, `Independent`, `Human`, and `Release`.

Allowed statuses are `PASS`, `NOT_OBSERVED`, `BLOCKED`, `FAIL`, and `NOT_APPLICABLE`. The audit aggregates the classes independently. A Synthetic or Contract result cannot satisfy Runtime, Independent, Human, or Release. In particular, `tests/HerdrOps.RuntimeTests` is WPF rendering against synthetic state and is always Synthetic evidence; its name never authorizes Runtime.

The version-local required classes are:

| Version | Required classes |
|---|---|
| v0.1.0 | Static, Synthetic, Human |
| v0.2.0 | Contract, Runtime |
| v0.3.0 | Synthetic, Integration, Runtime |
| v0.4.0 | Synthetic, Integration, Runtime, Independent |
| v0.5.0 | Contract, Integration, Runtime, Independent |
| v0.6.0 | Static, Synthetic, Contract |
| v0.7.0 | Runtime, Independent, Human, Release |

## Evidence manifest

An evidence manifest is optional only so the audit can report precise missing-gate blockers. When supplied, it must be strict JSON with `schemaVersion: 1`, the current `sourceCommit`, and one entry per version-local gate:

```json
{
  "schemaVersion": 1,
  "sourceCommit": "<40 lowercase hex characters>",
  "entries": [
    {
      "version": "v0.7.0",
      "gateId": "version-local",
      "issueNumber": 40,
      "reportPath": "artifacts/release-gates/v0.7.0/gate-report.txt",
      "reportSha256": "<64 hex characters>",
      "sourceCommit": "<same source commit>",
      "observedUtc": "2026-08-17T00:00:00Z",
      "sourceKind": "ReleaseAcceptance",
      "runtimeObserved": true,
      "sourcePaths": ["tools/Test-VersionMilestone.ps1"],
      "statuses": {
        "Static": "PASS",
        "Synthetic": "PASS",
        "Contract": "PASS",
        "Integration": "PASS",
        "Runtime": "PASS",
        "Independent": "PASS",
        "Human": "PASS",
        "Release": "PASS"
      },
      "artifacts": [
        {
          "path": "artifacts/publish/v0.7.0/HerdrOps.zip",
          "sha256": "<64 hex characters>",
          "sourceCommit": "<same source commit>"
        }
      ]
    }
  ]
}
```

The report path and every artifact path must be a repository-relative, non-traversing path. Existing path components and files are checked for reparse points. The report hash and every artifact hash are recalculated from the current bytes. A missing report/hash, stale source commit, wrong artifact commit, missing artifact, or hash mismatch is a blocker.

The JSON reader validates the RFC JSON grammar and rejects duplicate object keys before PowerShell parsing. The repository function is loaded unconditionally and resolved explicitly as a function so ambient functions or aliases cannot replace validation. Leading-zero numbers, comments, trailing commas, malformed GitHub responses, malformed fixtures, unknown evidence classes, duplicate entries, and missing required fields fail closed. Paged query metadata is admitted only when the callback endpoint exactly matches the requested endpoint and the recorded SHA-256 is recalculated successfully from the exact raw response text encoded as UTF-8.

## Query modes and output

When `gh` is available, the audit uses read-only `gh api` calls for milestones and issues. A committed or temporary offline fixture can be supplied with `-FixturePath`; this is deterministic validation input only. Offline mode always adds `OFFLINE_FIXTURE_NO_RELEASE_CREDIT` and can never produce Runtime, Independent, Human, Release, or release-candidate credit.

Reports are written only below `artifacts/dependency-audit/` and never overwrite an existing report. The JSON and text reports include:

- the exact source commit and clean-tree assertion;
- query source, endpoints/fixture identity, response hashes, and timestamp;
- hashes for all Plan truth files;
- stable, version/issue-sorted dependency mappings;
- separate evidence-class status objects;
- exact blocker codes and issue numbers;
- release-candidate status (`NOT_RECORDED` unless every gate is eligible).

Exit code `0` means a GitHub-backed audit is fully ready. Exit code `2` means a valid audit completed with `NOT_READY` blockers. Input, Git, path, JSON, or GitHub failures terminate without a report and are fatal. This preparation branch must use the latter outcomes; it must not freeze a candidate or claim release evidence.

## Commands

Read-only GitHub audit from a clean checkout:

```powershell
./tools/Invoke-V10Issue41DependencyAudit.ps1
```

Deterministic fixture validation:

```powershell
./tools/Test-V10Issue41DependencyAudit.ps1
```

The fixture tests are Synthetic validation of the audit tool. They do not observe Herdr, touch Registry/AppData/live databases, publish artifacts, or close Issue #41.

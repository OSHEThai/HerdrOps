## Purpose and authority

The Evaluation page presents explainable results from the versioned scoring
contract in `docs/protocol/v0.6-explainable-scoring-contract.md`. It is a
read-only presentation surface. It does not authorize review actions, mutate
evaluation records, ingest evidence, or infer live state from a missing source.

One immutable presentation snapshot is the only input to every card, chart,
dimension row, comparison value, and ranking on a page. The selected task and
Agent comparison must use the same snapshot as the summary and rankings. A
value that is missing, malformed, invalid, or unavailable remains visibly
missing or unavailable; it must never be converted to zero or a passing score.

## Approved hierarchy

The page preserves the shared HerdrOps shell: blue circular mark and wordmark,
top project/status bar, left navigation, content workspace, and bottom
connection/status bar. Within the workspace, the reference hierarchy is:

1. Five summary cards: average score today, total evaluations, Leader reviews
   pending, Project Manager reviews pending, and recurring issues.
2. Score distribution with a numeric/textual legend for every score band.
3. Seven-day score trend with date/value text available beside the plot.
4. Six-dimension breakdown for Goal Alignment, Acceptance Criteria, Technical
   Quality, Scope Compliance, Evidence, and Communication.
5. Selected task/Agent comparison table with the six dimension rows, the
   Leader, Project Manager, objective-evidence values, dimension weight, and
   weighted contribution.
6. Top-performing and low-performing Agent rankings with score, deterministic
   rank, trend/context, and provenance affordances.

The layout must remain usable at the reference desktop size and the compact
1366 x 768 size. Compact mode may scroll vertically, but it must not remove a
required region or hide missing-score semantics.

## Scoring and reconciliation

Every displayed score and percentage is derived from the retained formula and
input snapshot. The comparison table exposes the three distinct source slots
and the weighted result; the dimension breakdown and summary average reconcile
to those same result records. The page must show the formula/result or
provenance identity needed to trace a displayed value to its retained source.

Complete evaluations are eligible for ranking. Incomplete or invalid
evaluations remain visible with a localized status and are excluded from a
passing result and from ranking calculations. If no eligible value exists, the
page shows an explicit unavailable state. Equal scores use stable Agent and
evaluation identities as tie-breakers and show that the rank is tied; ordering
must not depend on collection order.

## Language and accessibility

Thai and English are separate presentation modes. Exactly one selected
language is rendered at a time: Thai mode must not append English translations,
and English mode must not append Thai translations. Product names, Agent names,
Task IDs, file paths, hashes, and protocol values remain literal identities.

Charts have an adjacent textual equivalent containing their categories,
values, units, and missing points. Status and severity are communicated with
text and accessible names in addition to color. Each analytical region,
summary group, chart, comparison table, ranking, and evidence-boundary marker
has a meaningful automation name. Focus and keyboard order follow the visual
hierarchy. The page remains understandable when color is unavailable.

## Evidence boundary

Evidence is reported by class and must not be promoted implicitly:

| Class | Issue #31 meaning | Boundary |
|---|---|---|
| Static | Source, XAML, catalog, reference identity, parse and token checks | Does not prove rendered behavior or runtime compatibility |
| Synthetic | Deterministic Evaluation state, missing-score state, language refresh and WPF captures | Does not prove compatibility with an installed Herdr instance |
| Contract | Presentation contract and source/test markers | Does not prove end-to-end product operation |
| Runtime | Observation against an installed Herdr session and Windows processes | Not supplied by this Issue #31 implementation gate |
| Independent Review | Role-distinct review of the implementation and evidence | Not supplied by this contract |
| Release | Packaged bytes, clean-machine install, runtime acceptance and approval | Not supplied; v0.6 remains not release-ready |

The implementation gate may report Static, Contract, and Synthetic evidence
when their exact artifacts pass. It must state explicitly:

`Actual Herdr Runtime: NOT OBSERVED / NOT CLAIMED`

Synthetic previews, screenshots, local tests, source hashes, and this contract
cannot close a live-runtime requirement, establish production score ingestion,
prove reviewer authority, or satisfy the v0.6 release gate.

## Acceptance mapping

- UI hierarchy and reference identity: the approved reference, contract tests,
  language tests, and required Thai/English WPF captures.
- Snapshot reconciliation: integration tests covering cards, distributions,
  trend, dimensions, comparison rows, and rankings from one immutable state.
- Missing-score behavior: a deterministic missing-score capture and test proving
  visible exclusion from passing and ranking results.
- Evidence separation: a generated Issue #31 gate report containing exact
  source, test, reference, TRX, and screenshot hashes and the explicit runtime
  boundary above.
